BlinkGTK 1.2.3-build3 リリースノート

リリース日: 2026-09-26 / Chromium: 154.0.8037.57 / 言語: 日本語 | English

レンダリングエンジンを Chromium 154 に更新しました。

build3 で直したこと

  • 独自スキーム (ebook:// など) で配った 5 MB 以上の音声を <audio> で開くと、アプリのウィンドウごと
    応答しなくなっていました     (#137)。本文を UI スレッドの上でデータパイプに最後まで書き込んでいたため、
    <audio> が途中で読むのをやめると、UI スレッドが待ち続けていました。一時停止中でも再生中でも起きます
    (2.5 MB は正常、5・10・151 MB は止まることを確かめました)。本文は受け手が読んだ分だけ裏で書くように
    直しました。151 MB (60 分) の音声でも、読み込みから再生の準備まで約 1 秒で進み、シークもできます。
    公開 API は変わりません。余分なメモリも使いません
  • 独自スキームの <audio> が出す範囲の要求は Range: bytes=0- の 1 回だけで、シークしても次の要求は
    出ないことを確かめました。範囲の要求に対応しても <audio> の読み込み方は変わらないので、この版では
    対応していません (fetch() に付けた Range はハンドラの前まで届きますが、応答は全体です)

build2 でできるようになったこと

ページを PDF ファイルに書き出せます

blink_web_view_print_to_pdf_with_options() で、用紙・余白・背景・ページ範囲を指定して
書き出せます。callback は PDF をファイルに書き終えてから 呼ばれ、失敗したときは理由が渡ります。
縦組み・ルビ・傍点・縦中横も PDF の上で組まれます。

BlinkPdfOptions* o = blink_pdf_options_new();
blink_pdf_options_set_paper_size(o, 8.27, 11.69);   /* A4 (インチ) */
blink_web_view_print_to_pdf_with_options(view, "/tmp/page.pdf", o, on_pdf, NULL);
blink_pdf_options_free(o);

スクロールする容器 (overflow: auto など) の中の本文は、ページに分けられません。容器に見えている
分だけが 1 ページに入ります (C API リファレンスの「PDF の書き出し」)。

ダウンロードを保存できます

blink_web_view_set_download_handler() のハンドラが保存先を返すと、そこに保存します
(NULL なら XDG の Download ディレクトリ、"" なら保存しない)。download-started シグナルで
BlinkDownload を受け取り、進捗・完了・失敗を知り、blink_download_cancel() で取り消せます。
ハンドラを付けていないビューでは保存しません。

リンク先と新しいウィンドウの開き方をアプリが決められます

decide-navigation シグナルで、今のビューで開く / 止める / 外部ブラウザで開く / 別のビューで開く /
新しいビューで開く、から選べます。window.open() で開いたページを新しいビューで受け取ると、
window.opener が保たれます。

カメラとマイクを使えます

getUserMedia() が permission-request を通るようになりました。許可すると実際に使えます
(1.2.3-build1 までは常に NotSupportedError)。

許可に後から答え、要求元を知り、決定を覚えさせられます

blink_permission_request_ref() で要求を持ったまま後で allow / deny できます。
要求元は blink_permission_request_get_origin()、埋め込み元は get_embedding_origin()。
blink_permission_request_set_remember() で決定を覚えさせると、次からは同じ要求が届きません。

HTTP 認証 (Basic など) にアプリが答えられます

blink_web_view_set_auth_handler() のハンドラに届きます。blink_web_view_auth_response() で
ユーザー名とパスワードを返します。2 件目以降の認証は、1 件ずつ順に届きます。

既定のフォントと最小文字サイズを選べます

blink_web_view_set_font_family() で明朝・ゴシック・等幅などの既定のフォントを、
blink_web_view_set_minimum_font_size() で最小文字サイズを指定できます。最小文字サイズは
ルビにも適用されます (本文 16px・下限 12px なら、ルビは 8px から 12px になります)。

独自スキームを初期化の前に登録できます

blink_gtk_register_scheme() を blink_gtk_init() の前に呼ぶと、環境変数
BLINKGTK_EXTRA_SCHEMES を使わずにスキームを登録できます。そのスキームのページには origin が付き、
fetch() が使えます。

window.blinkgtk をページの最初のスクリプトから使えます

1.2.3-build1 までは読み込みが終わってから入っていました。

画面へ出さない宣言の下でも撮影できます

提示ポリシーで画面への表示を止めている間でも、blink_web_view_capture_screenshot_async() を
呼ぶと 1 枚だけ表示して撮ります (1.2.3-build1 までは 2 秒で失敗していました)。

build2 で直したこと

  • swiftshader モードで画面に何も出なかった (KNAVI #151)。撮影と表示が止まる扱いを EGL にだけ
    適用します。WebGL の描画も表示されます
  • 解放関数の注記 (#130)。blink_handoff_meta_serialize() の戻り値は g_free() で解放します
    (ヘッダと文書が C 標準ライブラリの解放関数と読める書き方でした)。解放の仕方が書かれていなかった
    blink_web_view_get_devtools_url() / blink_web_view_get_url() などにも書きました
  • 既定の文字コード。blink_web_view_set_default_encoding() は 1.2.3-build1 の時点でもページに
    反映されていました (build1 の下の表の「まだ」は、ASCII だけのページで測った結果でした)。既定値が
    使われるのは、文字コードの指定が無く、自動判定も答えを出さないページだけです
  • blink_gtk_sandbox_init() の注記。Windows 版の devel ZIP の lib/blinkgtk_sandbox.lib で
    提供していること、Linux の共有ライブラリには無いこと (Linux では blink_gtk_init() を使う) を書きました
  • 覚えた許可を保存するとき、1 回の要求で 2 種類を覚えると片方が失われることがありました

build2 で挙動が変わるもの

  • blink_web_view_print_to_pdf() が実際に PDF を書き出します。 1.2.3-build1 までは
    window.print() を呼んで、ファイルを書かずに成功を返していました
  • PDF の書き出しのため、実行時に CUPS のライブラリ (libcups.so.2) が要ります。 RPM・DEB では
    依存として入ります。tarball では cups-libs (Fedora) / libcups2 (Debian・Ubuntu) を入れてください
  • RPM / DEB の /usr/bin/blinkgtk-simple-browser は /usr/bin/blinkgtk-browser になりました。
    旧名のリンクは残しません。指す先 (/usr/libexec/blinkgtk-0.1/blinkgtk_browser) は同じです
  • ダウンロードは、ハンドラを付けていないビューでは保存しません

build1 でできるようになったこと

JavaScript・画像・localStorage の有効/無効が効くようになりました

blink_web_view_set_javascript_enabled() などの設定が、ページに反映されるように
なりました。1.2.2 までは値を覚えるだけで、FALSE にしてもページのスクリプトは
実行されていました。

関数 1.2.3 (出荷形で実測)
blink_web_view_set_javascript_enabled() 効く (FALSE でページのスクリプトが止まる)
blink_web_view_set_images_enabled() 効く (FALSE で画像が読み込まれない)
blink_web_view_set_local_storage_enabled() 効く (FALSE で localStorage が使えない)
blink_web_view_set_default_font_size() 効く (30 を渡すと本文が 30px)
blink_web_view_set_default_encoding() まだ効きません (文字コードの指定が無いページは windows-1252 のまま)

スクリプトを止めたいページを扱うアプリは、この版に更新してください。
set_default_encoding() は原因を調べて次の版以降で扱います。

独自スキームで Web 開発の書き方がそのまま通るようになりました

  • ハンドラが out_mime に "text/html; charset=utf-8" のように引数を付けて返しても、
    HTML として表示されます。1.2.2 までは <pre> のテキストとして表示されていました。
    指定した charset はそのまま使います
  • BLINKGTK_EXTRA_SCHEMES に書いたスキームで、ページから fetch() が使えるように
    なりました。1.2.2 までは組み込みの 5 スキーム (app / blinkgtk / res /
    resource / ebook) だけでした

パッケージ版で、リソースの場所を指定せずに起動できます

blink_gtk_set_resources_path() を呼ばなくても、libblinkgtk の置き場所から
icudtl.dat などを探すようになりました。1.2.2 までは実行ファイルの隣しか見ておらず、
rpm / deb 版で自分のアプリを作ると ICU のエラーで起動できませんでした。
探す順は次のとおりです。

  1. 実行ファイルと同じディレクトリ
  2. <libdir>/blinkgtk-0.1/chromium/ (rpm / deb)
  3. <libdir>/chromium/ (tarball)
  4. <libdir>/

場所を指定するアプリは、これまでどおり動きます。

入力メソッドは GTK の選択に従います

日本語入力の経路を、BlinkGTK が決めずに GTK に任せるようにしました。Wayland では
GTK4 の既定である text-input 経路になり、入力メソッドの側 (IBus) が推奨する形です。
Fedora 45 / GNOME の実機で、この経路を選んだときに変換モードが通ることと、ビューを
繰り返し閉じても入力メソッドの警告が出ないことを確かめています (1.2.2 に入れた
切り替えで同じ経路を選んで測りました)。

1.2.2 と同じ動作 (IBus を名指しする) にしたい場合は、BLINKGTK_IM_MODULE=ibus を
指定してください。効くのは BlinkGTK のビューだけです。blink_gtk_get_im_module() で
いま設定している値を確かめられます (既定は空文字列 = GTK に任せる)。

計測したい区間に、自分で目印を打てます

blink_gtk_trace_mark("名前") を呼ぶと、トレースに目印が入ります。イベント名が
その名前になり、Web の performance.mark() と同じ形で並びます。

// 起動: --trace-startup=toplevel,blink.user_timing
blink_gtk_trace_mark("workload_ready");
/* ... 測りたい区間 ... */
blink_gtk_trace_mark("idle_static_ready");

カテゴリ blink.user_timing を足していなければ、この呼び出しは何もしません。

Chromium 154 で既定で有効になった機能

  • CSS text-decoration-inset — 下線・上線・打ち消し線を、文字列の端から内側へ
    寄せたり外側へ伸ばしたりできます。縦書きでは下線が傍線にあたります
  • 大きさが中身に合う <iframe> — 中の文書に合わせて親側で寸法を決められます
    (指定したときだけ)
  • @font-face の font-width 記述子 — font-stretch の別名です

機能の一覧は chromestatus.com の Chromium 154 のものです。当方で実測したのは
上記の縦組みに関わるものではなく、描画・入力・起動の範囲です。

build1 で直したこと

  • 1.2.1 で入れた独自の回避 (縦組みで閉じ括弧が行末に来ると行が途中で切れる件) を
    取り除きました。Chromium 153 で上流が同じ症状を直しており、1.2.2 では回避が
    結果を変えていないことを測ったうえで、1.2.2 には残していました

  • load-failed シグナルのヘッダの注記が実装と違っていました。ハンドラの正しい形は
    次のとおりです (シグナル自体は変えていません)

    static void on_load_failed (BlinkWebView *web_view, BlinkLoadError error_code,
                            const char *failing_uri, gpointer user_data);

  • blink_gtk_init_with_sandbox() をヘッダは「共有ライブラリにまだ無い」と書いて
    いましたが、1.2.2-build4 から入っています。Linux では NULL を渡すと
    blink_gtk_init() と同じ動作です

この版で変わらないこと

  • 公開 API の削除はありません。前版向けにビルドしたアプリはそのまま動きます
  • 描画経路 (software / EGL) の既定と切り替え方法は前版と同じです

挙動が変わるもの

  • 入力メソッドの既定 (上記)。以前の動作は BLINKGTK_IM_MODULE=ibus で戻せます
  • 1.2.2 までは効いていなかった 4 つの設定が効きます。FALSE を渡していたアプリでは、
    ページのスクリプトや画像が止まるようになります

動作を確かめた範囲

  • EGL 経路: 白画面・描画の縮小・異常終了の 3 点をログで判定する検査に通しています
  • 設定の反映: set_javascript_enabled(FALSE) でページのスクリプトが止まることを、
    出荷形で確かめています (1.2.2 では同じ検査が失敗することも確かめています)。
    画像・localStorage・既定の文字サイズも出荷形で確かめ、既定の文字コードは
    効かないことを確かめています
  • 独自スキームとリソースの自動検出: MIME の引数・fetch()・リソースを指定しない
    起動の 3 点を、出荷形で確かめています (1.2.2 では 3 点とも失敗)
  • 入力メソッド: Fedora 45 / GNOME の実機で、2 つの経路をそれぞれ 40 回ビューを
    閉じて確かめています (1.2.2 の切り替えで経路を選んで測定。1.2.3 の既定で
    その経路が選ばれることは、起動時のログで確かめています)
  • 目印: 同じトレースの中で、blink_gtk_trace_mark() と performance.mark() の
    目印がどちらも名前のままイベントになることを確かめています
