BlinkGTK 1.2.3-build1 リリースノート

リリース日: 2026-09-24 / Chromium: 154.0.8037.57 / 言語: 日本語 | English

レンダリングエンジンを Chromium 154 に更新しました。

build1 でできるようになったこと

JavaScript・画像・localStorage の有効/無効が効くようになりました

blink_web_view_set_javascript_enabled() などの設定が、ページに反映されるように
なりました。1.2.2 までは値を覚えるだけで、FALSE にしてもページのスクリプトは
実行されていました。

関数 1.2.3 (出荷形で実測)
blink_web_view_set_javascript_enabled() 効く (FALSE でページのスクリプトが止まる)
blink_web_view_set_images_enabled() 効く (FALSE で画像が読み込まれない)
blink_web_view_set_local_storage_enabled() 効く (FALSE で localStorage が使えない)
blink_web_view_set_default_font_size() 効く (30 を渡すと本文が 30px)
blink_web_view_set_default_encoding() まだ効きません (文字コードの指定が無いページは windows-1252 のまま)

スクリプトを止めたいページを扱うアプリは、この版に更新してください。
set_default_encoding() は原因を調べて次の版以降で扱います。

独自スキームで Web 開発の書き方がそのまま通るようになりました

  • ハンドラが out_mime に "text/html; charset=utf-8" のように引数を付けて返しても、
    HTML として表示されます。1.2.2 までは <pre> のテキストとして表示されていました。
    指定した charset はそのまま使います
  • BLINKGTK_EXTRA_SCHEMES に書いたスキームで、ページから fetch() が使えるように
    なりました。1.2.2 までは組み込みの 5 スキーム (app / blinkgtk / res /
    resource / ebook) だけでした

パッケージ版で、リソースの場所を指定せずに起動できます

blink_gtk_set_resources_path() を呼ばなくても、libblinkgtk の置き場所から
icudtl.dat などを探すようになりました。1.2.2 までは実行ファイルの隣しか見ておらず、
rpm / deb 版で自分のアプリを作ると ICU のエラーで起動できませんでした。
探す順は次のとおりです。

  1. 実行ファイルと同じディレクトリ
  2. <libdir>/blinkgtk-0.1/chromium/ (rpm / deb)
  3. <libdir>/chromium/ (tarball)
  4. <libdir>/

場所を指定するアプリは、これまでどおり動きます。

入力メソッドは GTK の選択に従います

日本語入力の経路を、BlinkGTK が決めずに GTK に任せるようにしました。Wayland では
GTK4 の既定である text-input 経路になり、入力メソッドの側 (IBus) が推奨する形です。
Fedora 45 / GNOME の実機で、この経路を選んだときに変換モードが通ることと、ビューを
繰り返し閉じても入力メソッドの警告が出ないことを確かめています (1.2.2 に入れた
切り替えで同じ経路を選んで測りました)。

1.2.2 と同じ動作 (IBus を名指しする) にしたい場合は、BLINKGTK_IM_MODULE=ibus を
指定してください。効くのは BlinkGTK のビューだけです。blink_gtk_get_im_module() で
いま設定している値を確かめられます (既定は空文字列 = GTK に任せる)。

計測したい区間に、自分で目印を打てます

blink_gtk_trace_mark("名前") を呼ぶと、トレースに目印が入ります。イベント名が
その名前になり、Web の performance.mark() と同じ形で並びます。

// 起動: --trace-startup=toplevel,blink.user_timing
blink_gtk_trace_mark("workload_ready");
/* ... 測りたい区間 ... */
blink_gtk_trace_mark("idle_static_ready");

カテゴリ blink.user_timing を足していなければ、この呼び出しは何もしません。

Chromium 154 で既定で有効になった機能

  • CSS text-decoration-inset — 下線・上線・打ち消し線を、文字列の端から内側へ
    寄せたり外側へ伸ばしたりできます。縦書きでは下線が傍線にあたります
  • 大きさが中身に合う <iframe> — 中の文書に合わせて親側で寸法を決められます
    (指定したときだけ)
  • @font-face の font-width 記述子 — font-stretch の別名です

機能の一覧は chromestatus.com の Chromium 154 のものです。当方で実測したのは
上記の縦組みに関わるものではなく、描画・入力・起動の範囲です。

build1 で直したこと

  • 1.2.1 で入れた独自の回避 (縦組みで閉じ括弧が行末に来ると行が途中で切れる件) を
    取り除きました。Chromium 153 で上流が同じ症状を直しており、1.2.2 では回避が
    結果を変えていないことを測ったうえで、1.2.2 には残していました

  • load-failed シグナルのヘッダの注記が実装と違っていました。ハンドラの正しい形は
    次のとおりです (シグナル自体は変えていません)

    static void on_load_failed (BlinkWebView *web_view, BlinkLoadError error_code,
                            const char *failing_uri, gpointer user_data);

  • blink_gtk_init_with_sandbox() をヘッダは「共有ライブラリにまだ無い」と書いて
    いましたが、1.2.2-build4 から入っています。Linux では NULL を渡すと
    blink_gtk_init() と同じ動作です

この版で変わらないこと

  • 公開 API の削除はありません。前版向けにビルドしたアプリはそのまま動きます
  • 描画経路 (software / EGL) の既定と切り替え方法は前版と同じです

挙動が変わるもの

  • 入力メソッドの既定 (上記)。以前の動作は BLINKGTK_IM_MODULE=ibus で戻せます
  • 1.2.2 までは効いていなかった 4 つの設定が効きます。FALSE を渡していたアプリでは、
    ページのスクリプトや画像が止まるようになります

動作を確かめた範囲

  • EGL 経路: 白画面・描画の縮小・異常終了の 3 点をログで判定する検査に通しています
  • 設定の反映: set_javascript_enabled(FALSE) でページのスクリプトが止まることを、
    出荷形で確かめています (1.2.2 では同じ検査が失敗することも確かめています)。
    画像・localStorage・既定の文字サイズも出荷形で確かめ、既定の文字コードは
    効かないことを確かめています
  • 独自スキームとリソースの自動検出: MIME の引数・fetch()・リソースを指定しない
    起動の 3 点を、出荷形で確かめています (1.2.2 では 3 点とも失敗)
  • 入力メソッド: Fedora 45 / GNOME の実機で、2 つの経路をそれぞれ 40 回ビューを
    閉じて確かめています (1.2.2 の切り替えで経路を選んで測定。1.2.3 の既定で
    その経路が選ばれることは、起動時のログで確かめています)
  • 目印: 同じトレースの中で、blink_gtk_trace_mark() と performance.mark() の
    目印がどちらも名前のままイベントになることを確かめています
