BlinkGTK for Windows — はじめかた

数字には測った日を添えてあります。 配布物のサイズと同梱文書の本数は
配布する ZIP そのものの実測値 (2026-09-27 実測) です。
注意: ZIP を組み立てた日時はここには書きません。 組み直すたびに変わるためです。
ZIP の正確なバイト数とハッシュは、配布物と一緒に置く <パッケージ名>.verify.json (size / sha256)
と SHA256SUMS (ハッシュのみ) を見てください。
この版は、Windows 11 Pro build 26200 で 2026-09-27 に確認しました (配布物の展開実行検査)。

BlinkGTK を Windows で使えるようにしたものです。版数体系も同じ
(Chromium の版 + BlinkGTK のパッチレベル) です。
この版 1.2.3-build3 は、Linux 版の 1.2.3-build3 と同じ版数で、どちらも Chromium 154.0.8037.57 です。

公開 API は、Linux 版 1.2.3-build3 と 1 本を除いて同じです。
ただし、この版で Windows 版に新しく入った 51 本 (Linux 版の 1.2.2 と 1.2.3 で加わったもの) は、
Windows ではまだ呼んで確かめていません。Windows で呼んで確かめたのは公開 API 152 本のうち 64 本で
(同梱の docs\api-windows-notes-ja.md の §0)、どれも前の版から在った API です。

数え方: 公開ヘッダの宣言と、共有ライブラリ (.so / .dll) の export の
両方に在るものを公開 API と数えます。ヘッダの宣言には、G_DECLARE_FINAL_TYPE が宣言する
_get_type の 2 本 (BlinkWebView / BlinkDownload) も含めます。
この定義で Linux は 153 件、Windows は 152 件です。

測り方 (どちらも 2026-09-27 実測):
Linux は本体が公開した 1.2.3-build3 の devel パッケージのヘッダと、runtime パッケージの .so を
nm -D で見て、ヘッダ宣言 154 と、export のうち blink_ で始まる名前 189 の共通部分で 153。
Windows はこの版の公開ヘッダの宣言 153 と、DLL の export (dumpbin /exports) のうち blink_ で始まる名前
163 の共通部分で 152。
名前で絞るのは、ヘッダに無い内部のシンボルを数えないためで、共通部分の件数には影響しません。
Windows のヘッダの 153 は、#ifndef _WIN32 の中の blink_web_view_attach_to_external_surface を除き、
blink_gtk_sandbox_init を含む数です。同梱の docs\api-windows-notes-ja.md の §0 は
BLINKGTK_EXPORT の付いた宣言を数えており (こちらは前者を含み後者を含まない)、同じ 153 でも中身が違います。
共通部分の 152 は同じです。
注意: 両 OS で数え方をそろえたうえで、条件コンパイルの扱いだけ対称にしてあります —
Windows 側は #ifndef _WIN32 の中を、Linux 側は #ifdef _WIN32 の中を除きます
(その platform の利用者に見えない宣言を数えないため)。

Windows に無い blink_web_view_attach_to_external_surface (Wayland 固有) の 1 本
Windows にだけある なし

上の件数には入らないものが 1 本あります。
blink_gtk_sandbox_init() はヘッダには両方で宣言されていますが、どちらの共有ライブラリも export しません。
Windows では静的ライブラリ blinkgtk_sandbox.lib 経由で実行ファイルに取り込む設計です (devel ZIP に同梱)。
Linux ではこれを呼べません (下記)。

サンドボックスの 2 本について (2026-09-27 実測。export は、Linux の .so を nm -D、Windows の DLL を dumpbin /exports で確認):

Linux 1.2.3-build3 この Windows 版
ヘッダの宣言 あり (2 本とも) あり (2 本とも)
blink_gtk_init_with_sandbox() を共有ライブラリが提供 あり あり
blink_gtk_sandbox_init() を提供 なし あり (静的ライブラリ blinkgtk_sandbox.lib を devel ZIP に同梱)

blink_gtk_sandbox_init() は Windows 専用で、Linux では呼べません。
ヘッダ (英文) は、この関数を "Windows only." とし、Linux については
"The Linux shared library does not export it, so calling it there fails to link." と書いています
(Linux の共有ライブラリはこの関数を export していないので、Linux で呼ぶとリンクに失敗する、の意)。
Linux では、blink_gtk_init() を使うか、blink_gtk_init_with_sandbox() に NULL を渡します。
両方の OS で同じコードを使う場合は、呼び出しを #ifdef G_OS_WIN32 で囲めます (同じヘッダの注記による)。
同じヘッダは、Windows での提供元を、BlinkGTK for Windows の devel ZIP の lib/blinkgtk_sandbox.lib
(1.2.1-build3 から) としています。Since: は、blink_gtk_sandbox_init() が 1.2.1、
blink_gtk_init_with_sandbox() が 1.2.2 です。
この注記は、Linux 1.2.3-build3 の devel のヘッダとこの版のヘッダで同じ文面です (2026-09-27 に比べて確認)。
blink_gtk_init_with_sandbox() の注記が参照している issue #141 は、当方が本体リポジトリに立てた相談です。

何が入っていますか

portable ZIP 展開してすぐ動きます。GTK4 も同梱しているので、別途の導入は要りません
devel ZIP 組み込む人向け。公開 API ヘッダ、インポートライブラリ、GTK4 の開発用ファイル

インストーラ (MSI) はまだありません。設計だけ決まっています。

動かすまで

1. 展開する

ZIP を任意の場所へ。管理者権限は要りません。

2. 初回は警告が出ることがあります

この配布物にはコード署名がありません。 そのため、ブラウザで取得して実行すると
Microsoft Defender SmartScreen の警告が出ることがあります。案内に従って実行を
続けてください。

署名は後から追加できるため、署名なしで出しています。

注意: この画面のスクリーンショットはまだありません。
当方の開発機では配布物をブラウザ経由で取得していないため、Mark of the Web が付きません。
つまり開発機ではこの警告を再現できません。 素の Windows で取得から実行まで
通して撮り次第、画面と実際のボタン名を載せます。

3. 実行する

bin\blinkgtk_browser.exe を実行します。
引数を付けないと https://google.com/ を開きます (インターネットへの接続が要ります)。
引数に URL を渡すと、そのページを開きます。

cd blinkgtk-1.2.3-build3-windows-x64\bin
blinkgtk_browser.exe
blinkgtk_browser.exe https://example.com/

blinkgtk_browser は、BlinkGTK を組み込むのに必要なものだけを示す最小構成のサンプルです。
起動すると、コンソールウィンドウも開いて動作のログが表示されます。

動作条件

OS Windows 10 (64bit) 以降
CPU x64 (32bit は対応しません)
空き容量 ZIP 約 464 MiB + 展開後 約 1,316 MiB。展開中は両方必要なので実質 約 1.8 GiB (1,780 MiB を切り上げ。2026-09-27 実測)
GTK4 同梱。別途入れないでください
VC++ ランタイム DLL を同梱 (再頒布可能パッケージのインストーラは不要)

注意: 本ページの MiB は 1,048,576 バイトです。 GitHub の Releases の画面も
同じ単位で「MB」と表示するので、Releases では 464 MB と見えます
(2026-09-23 に、公開されている別のリポジトリのリリースで、API のバイト数と画面の表示を突き合わせて確認)。
1,000,000 バイト単位で数えるツールでは 487 MB と出ます。
同梱文書も同じ単位で書いています — 大きさを書いている 6 本
(INSTALLATION-ja.md / INSTALLATION-en.md / building-with-blinkgtk-ja.md /
portable-app-guide-ja.md / faq-ja.md / linux-windows-differences-ja.md)
すべてで、MB が MiB であることを明記しています (2026-09-27 時点。機械で確認)。

GTK4 を別途インストールしないでください。 Windows の GTK4 には ABI が
2 系統あり (gvsbuild = MSVC ABI / MSYS2 = MinGW ABI)、別の ABI でビルドした
ものは同梱の GTK4 とリンクできません。
(一般論です。当方で実際に混ぜて試したわけではありません。)

注意: 当方が確認したのは Windows 11 Pro (build 26200) です。
Windows 10 では確かめていません。

注意: 描画結果を GTK へ渡す経路は software の 1 つだけです。
EGL の描画経路そのもの (blink_web_view_egl.cc / blink_wayland_surface.cc)
を Windows のビルド対象に入れていないためです。描画を受け取る側のサーフェスをどう合成するかが
未設計で、DirectComposition を使う形を検討中です。
blink_gtk_ensure_egl_recipient() などは、公開ヘッダに宣言の無い export として
ABI を保つため blinkgtk.dll に残っていますが、Windows では 0 を返します。

環境変数 BLINKGTK_GPU_MODE は読まれます (2026-09-27 に、この版で確認)。

  • egl を指定すると、Chromium を --disable-gpu なしで起動し、経路名の申告が "P3" になります。
    このとき ANGLE のウィンドウも作られていたので、Chromium の中では GPU を使う描画が
    行われている可能性があります (どこまで GPU を使うかは測っていません)。
    GTK へ描画結果を渡す部分は software のときと同じです。
  • swiftshader は Windows では software と同じ扱いです (--disable-gpu を付けます)。

cmd で指定するときは set "BLINKGTK_GPU_MODE=egl" のように引用符で囲んでください。
set BLINKGTK_GPU_MODE=egl && … と書くと値の末尾に空白が付き、egl と一致しません。

Linux 版との違い

Linux Windows
導入 RPM / DEB / tarball ZIP (MSI は今後)
GTK4 OS のパッケージ 同梱
描画結果の受け渡し経路 software / EGL software のみ (EGL は組み込んでいません)
blink_web_view_attach_to_external_surface あり ありません (Wayland 固有)
日本語縦組みの版面 (既定) 列格子 snap は既定 OFF 列格子 snap の差はありません
同 (フラグ CJKVerticalColumnFragmentation を有効にしたとき) 版面の計算を変える改変 4 箇所 (まとめて列格子 snap と呼びます) が働く 入っていません — 列への分け方や行の位置が違いうる (下記)

注意: 縦組みの版面が両 OS で一致する保証はありません。

縦組みの版面の改変が Windows に入っていません。ただし既定では Linux でも
その改変は働きません。
改変を働かせるフラグ CJKVerticalColumnFragmentation は BlinkGTK が足したもので
(Chromium 上流の機能ではありません)、runtime_enabled_features.json5 で
status: "experimental" = 既定 OFF です。製品コードがこれを
有効にすることもありません。

数え方 (2026-09-27 実測。本体の 1.2.3-build3 のツリーと、この版の Windows のツリー):
強制的に有効化する SetCJKVerticalColumnFragmentation... の呼び出しを本体のツリー全体で数えて
0 件。コマンドラインでの有効化 (--enable-blink-features) も製品コードには
無く、third_party/blinkgtk/ での出現は 0 件です。

フラグが有効になるのは、起動時に次のどちらかを付けたときです。

  • --enable-blink-features=CJKVerticalColumnFragmentation
  • --enable-experimental-web-platform-features (status: "experimental" の機能をまとめて有効にする
    Chromium のスイッチ。Chromium の content/child/runtime_features.cc:576,586)

Windows では、どちらも実行ファイルのコマンドラインに付けてください。
Chromium は引数を GetCommandLineW から取るので、組み込み側で blink_gtk_init() に
argv を渡しても届きません。
縦書き版面メトリクスの JS の API (window.__blinkgtk.verticalFlowMetrics) を使う場合は、
このフラグが要ります。Windows でも、上の 2 通りのどちらでも API が用意され、
呼ぶとオブジェクトが返ることを確かめています (2026-09-27、縦書き 2 段組みの試験ページ)。

フラグを有効にしたときの違い: Linux 版では、版面の計算を変える条件式が 4 箇所働きます。
段組みの容器の直接の子で列の分割に加わっていない block の大きさを列幅 (column-width が auto のときは 600px) の倍数へ
切り上げる、列の境界をまたぐ行を列の格子に合わせる、列の高さが決まっていない縦書きの段組みで列の高さを確定させる、
書字方向が直交する縦書きの子を段組みの分割に参加させる、の 4 つです (本体の 1.2.3-build3 のツリーの
block_layout_algorithm.cc:1418, 2888 / column_layout_algorithm.cc:374 /
fragmentation_utils.cc:357)。本体はこれらをまとめて「SNAP 系 4 箇所」と呼んでおり、
本ページの列格子 snap もこの 4 つ全体を指します。この Windows 版の該当 3 ファイルには出現 0 件で、どれも働きません。
そのため、列への分け方や行の位置が Linux 版と違いうると見ておいてください。

行分割のソースは両 OS で同じです (2026-09-27、md5 で比較)。Blink の
core/layout/inline・platform/fonts/shaping・platform/text 直下の .cc / .h 275 本のうち、
違うのは 2 本で、1 本はコメントだけ、もう 1 本は開発用の環境変数を設定したときだけ出る
診断出力 (Linux 側のみ) の差でした。runtime_enabled_features.json5 も同一です。
以前の版 (Windows = Chromium 152) で挙げていた行分割の違いは、この版にはありません。

注意: 両 OS の描画結果 (スクリーンショット) を並べて比べてはいません。
確かめたのはソースの差までで、画面上どれだけ違うかは測っていません。
フォントなど、ソース以外の違いも比べていません。
版面メトリクスの API が返す値が Linux と一致するかも測っていません。

詳細は同梱の docs\environment-variables-ja.md の §2-b (縦書き版面メトリクスの API)。

組み込む方

devel の ZIP に、公開 API ヘッダとインポートライブラリが入っています。

ビルドには Visual Studio Build Tools と Windows SDK が別途要ります
(当方の確認は Visual Studio Build Tools 2026 です)。
(GTK4 を別途入れなくてよいのは、動かす場合の話です)

利用者側のコンパイルには /MD /DCOMPONENT_BUILD が要ります。
リンクするライブラリなど、ビルドの手順は同梱の docs\building-with-blinkgtk-ja.md を見てください。
日本語の Windows で MSVC を使う場合は、/utf-8 も付けてください。
付けないと、ヘッダがコードページ 932 として読まれ、公開ヘッダの日本語のコメント (UTF-8) や
GTK のヘッダの © などの記号で警告 C4819 が出ます。

公開ヘッダは blink_gtk.h が #include <gtk/gtk.h> するため、GTK4 の
開発用ファイルも同梱しています。

組み込み時の注意が 3 点あります (1 点目は Windows 固有)。

  1. ヘッダを include したうえで、公開 API の前方宣言を自分でも書かないでください (Windows 固有)。
    ヘッダは __declspec(dllimport) 付きで宣言しているので、同じ翻訳単位に dllimport の
    付かない宣言が並ぶと、clang では警告が出ます
    (ヘッダが先なら -Winconsistent-dllimport、自前の宣言が先なら -Wdll-attribute-on-redeclaration)。
    警告をエラーとして扱う設定 (-Werror / /WX) ではビルドが止まります
    (MSVC の cl.exe での出方は当方では確かめていません)。前方宣言は書かず、ヘッダだけを使ってください。

  2. 呼び出し側が解放する戻り値は g_free() で解放してください。
    blink_handoff_meta_serialize() が例です。実装が g_strdup_printf() で
    確保しているので、契約としては g_free() です。

    API リファレンスとその掲載例は 1.2.3-build1 まで free() でしたが、
    1.2.3-build2 でヘッダとともに g_free() に直りました (#130)。なお現行の構成で free() が壊れる、
    という意味ではありません — Windows でも blinkgtk.dll と
    glib-2.0-0.dll はどちらも CRT を DLL (UCRT) から使っています
    (この版で dumpbin /dependents により確認、2026-09-27)。揃えるのは契約のためです。

  3. blink_gtk_sandbox_init() は DLL からエクスポートされません。
    静的ライブラリ blinkgtk_sandbox.lib 経由で実行ファイルに取り込む設計です
    (devel ZIP に同梱)。この API は Windows 専用で、Linux では呼べません
    (Linux の共有ライブラリは export していません。Linux での代わりの呼び方は、上の「サンドボックスの 2 本について」を参照)。
    経緯は本体リポジトリの issue #141 (当方が立てた相談) です。
