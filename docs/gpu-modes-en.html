BlinkGTK GPU Modes

BlinkGTK lets you choose whether pages are drawn with the GPU, from three modes.
This page covers how to choose, how to set the mode, what can be switched while the app is running, and what to check when something goes wrong.

1. Which mode to choose

Situation Mode How
Not sure / no GPU / CI software Set nothing (default)
Desktop with a GPU, and you want the GPU to draw egl BLINKGTK_GPU_MODE=egl
No GPU, but pages use WebGL / WebGPU swiftshader BLINKGTK_GPU_MODE=swiftshader
  • With nothing set, BlinkGTK runs in software mode. It does not depend on GPU drivers, so pages look the same everywhere
  • Every mode needs a Wayland compositor to display pages. On CI without a screen, use a headless compositor (such as weston's headless backend)
  • If you set egl on a machine where the GPU cannot be used, BlinkGTK switches to software automatically. When no frame arrives for 5 seconds, it switches to software, keeps showing the page, and prints the reason to standard error (since 1.2.1-build2). On machines where the GPU works, it does not switch
  • WebGL / WebGPU are not available in software mode. For pages that use them, choose egl or swiftshader (see the table below)

2. The three modes

software swiftshader egl
Page drawing CPU CPU (compositing is the same as software) GPU
WebGL / WebGL 2 Not available Available (computed on the CPU) Available
WebGPU Not available Available (computed on the CPU) Available
GPU and driver Not needed Not needed Needed (with Wayland EGL support)
Good for E-book readers, kiosks, CI 3D pages on machines without a GPU Desktops with a GPU

WebGL / WebGPU availability was checked on the Chromium 155 build by trying each mode (2026-10-13). The calls tried were getContext('webgl'), getContext('webgl2') and navigator.gpu.requestAdapter().

software

  • Blink draws the page on the CPU, and BlinkGTK shows the result in the GTK window
  • How the result is received depends on the display scale at startup (since 1.2.4)
    • When every display has scale 1: the result is received through mojo shared memory. No capture and read-back of the result is needed, and compositing only redraws the changed area, so pages that change in small areas use less CPU
    • Otherwise: the result is captured and received each time
    • If the window moves to a display with a scale above 1 after startup, BlinkGTK switches back to capturing, once. When it does, a render-path-changed signal arrives even though the app did not ask for a switch
  • To receive the result the way earlier versions did (by capturing), set BLINKGTK_T2_AUTO=0 or BLINKGTK_USE_MOJO_IPC=0. If BLINKGTK_USE_MOJO_IPC is set, that setting is followed. If --force-device-scale-factor is given, its value is used for the decision, and BlinkGTK does not switch back when the window moves to another display

swiftshader

  • Page compositing is the same as software; only WebGL / WebGPU work is done by SwiftShader (a library that does the GPU's work on the CPU)
  • SwiftShader and the files needed to load it are included in the distribution
  • In 1.2.3-build1 and some other versions, nothing could appear on screen in this mode. This was fixed in 1.2.3-build2

egl

  • Draws on the GPU through Wayland EGL and hands the result to the GTK window while it stays in GPU memory (dmabuf). The result is not read back to the CPU for display (the first few frames after startup, the first frame after switching to the GPU hand-over, and captures are read on the CPU)
  • Needs a real GPU and a driver with Wayland EGL support
  • Setting BLINKGTK_GPU_MODE=egl is all that is needed (since 1.2.0-build3; earlier versions show a white screen)
  • While the window is being resized, it may turn white for a moment

3. How to set the mode

Decide before startup. Either of these works the same way.

BLINKGTK_GPU_MODE=egl ./myapp
blink_gtk_set_gpu_mode(BLINK_GPU_MODE_EGL);   /* call before blink_gtk_init() (since 1.2.2-build5) */
blink_gtk_init(&argc, &argv);
  • If both the environment variable and blink_gtk_set_gpu_mode() are used, blink_gtk_set_gpu_mode() wins
  • The mode is fixed inside blink_gtk_init(). Calling blink_gtk_set_gpu_mode() afterwards does not change it; it only prints a warning
  • blink_web_view_new_with_gpu_mode() also cannot select the mode after blink_gtk_init(), because the mode is already fixed when a WebView is created. Use one of the two ways above
  • There is one mode per process. It cannot differ between WebViews
  • blink_web_view_get_gpu_mode() tells you the mode fixed at startup. The startup log also prints "描画経路=" (rendering path = mode). After an automatic switch from egl to software, this value still says egl (section 5)

4. Switching while running (BlinkShift)

BlinkShift is the feature that switches how the drawn result is handed to the screen, without restarting the app (since 1.2.0-build9).
Request a switch with blink_web_view_switch_render_path(); the result arrives in the render-path-changed signal.
blink_web_view_get_render_path() tells you the current method.

int seq = blink_web_view_switch_render_path(view, "P1");
/* Returns 1 or more if accepted, 0 if not.
 * The result arrives in render-path-changed (path_id, result, gate_ms, seq). */

Values to pass:

Value How the result is handed over
"P1" The software result is captured and received each time
"P2" The software result is received through mojo shared memory
"P3" The GPU (egl) result is received while it stays in GPU memory

The result is one of three values.

result Meaning
"ok" Drawing works with the new method
"rollback" Drawing could not be confirmed with the new method, so BlinkGTK went back to the previous method. The screen is left as it was
"fail" The previous method could not be restored, or the switch could not start. Treat it as an error

What can switch to what (Chromium 155, a machine with a GPU, display scale 1; each tried once on a headless compositor, 2026-10-13):

Started in Can switch to Cannot switch to
software "P1" ↔︎ "P2" (tens to hundreds of milliseconds) "P3" (egl) — not accepted, or rolled back
egl "P1" (about 250 ms) "P2"

0 is returned (the request is not accepted) in cases such as:

  • The first frame has not been delivered yet
  • The result is received through mojo shared memory ("P2") or GPU memory ("P3"), and anything other than capturing ("P1") is requested
  • An unknown value, NULL or an empty string is passed
  • Automatic switching for diagnostics is running through the environment variable BLINKGTK_BLINKSHIFT_AUTOSWAP

Notes:

  • A process started in software cannot move to egl while running. To draw with egl, start the app again with BLINKGTK_GPU_MODE=egl
  • To carry state over the restart, you can use blink_web_view_export_handoff_meta() / blink_web_view_import_handoff_meta()
    • The exported meta holds the URL, the size of the view (logical pixels), the display scale (an integer) and the mode name (the value of the environment variable BLINKGTK_GPU_MODE). The scroll position fields are written as 0, so fill them in yourself if you need them
    • Import only loads the URL. Set the window size yourself, and restore the scroll position with JavaScript after loading
    • To pass the meta to another process, turn it into a string with blink_handoff_meta_serialize() / blink_handoff_meta_deserialize()
  • A switch applies to the view of the first WebView in the process that received a frame. With several WebViews, the view argument only decides where the result is reported
  • For how to use seq, see the render-path-changed section of the Signals API reference. For details of the meta, see Render path switching and hand-over

When you want to stop passing frames to the screen (presentation policy)

If you do not want to change the method but simply do not need to show anything right now
(for example while only audio is being heard), use blink_web_view_set_presentation_policy().
It saves only the cost of handing frames to the screen; page layout and drawing (look-ahead) continue.
While stopped, a capture request (such as blink_web_view_capture_screenshot_async()) still
produces one frame for the capture and then stops again (since 1.2.3-build2). In egl mode it currently has no effect.

5. Troubleshooting

I set egl but it seems to run in software

  • On machines where the GPU cannot be used, BlinkGTK switches to software after 5 seconds and prints the reason to standard error. Use that warning on standard error to tell whether the switch happened. blink_web_view_get_gpu_mode(), "描画経路=" in the startup log, blink_web_view_get_render_path() and the mode name in an exported handoff meta still report egl (the GPU-memory method, "P3") after the switch
  • To turn off the automatic switch, set BLINKGTK_EGL_AUTO_FALLBACK=0 (the screen then stays white if the GPU cannot be used). The wait time can be changed with BLINKGTK_EGL_AUTO_FALLBACK_MS
  • Check that you do not set the mode after blink_gtk_init() (section 3)

The screen stays white

  1. Has loading finished (does the load-changed signal deliver BLINK_LOAD_FINISHED)?
  2. Does a simple colored page appear (data:text/html,<body style='background:red'>TEST</body>)? In data: URLs, do not write colors with #; everything after # is cut off
  3. For egl, do the GPU and driver support Wayland EGL? If not, BlinkGTK should switch to software automatically (above)

If it is still white, please report it with the version (the value of blink_gtk_get_version_full()), the mode, and the window size and display scale.

With egl, the page appears small in the top-left corner

This happened when the display scale was not 1, and was fixed in 1.2.0-build3. egl takes the display scale from the first display at startup. Setups where displays have different scales, and moving the window to a display with a different scale after startup, have not been checked. If you see it, please report it with the window size and the scale of each display.
