BlinkGTK 環境変数リファレンス

作成者: BlinkGTK Project
最終更新: 2026-10-19 (BlinkGTK 1.2.4-build4 / Chromium 155.0.8059.39)

API リファレンスマニュアルの第 9 章 (環境変数) にあたる文書です。BlinkGTK が読む環境変数は、すべてこの一覧に載せています。ここに無い名前は BlinkGTK では使われません。

環境変数は次の 3 つに分けています。BlinkGTK を組み込むアプリが頼ってよいのは、1 つ目の「公開サポート」だけです。

  • 公開サポート — 安定 API。後方互換を維持し、変更時はリリースノートで告知します。
  • エスケープハッチ (切り分け用のスイッチ) — 既定で有効になっている修正や仕組みを止めて、以前の動作に戻すためのスイッチ。通常は設定しないでください。不具合の原因がその修正にあるかを確かめるときだけ使い、常用しないでください (将来の版で、予告のうえ削除することがあります)。
  • 内部診断 — 開発・調査用。無保証・サポート対象外で、予告なく変更・削除されます。アプリから頼らないでください。

1. 公開サポート環境変数

変数 値 既定 説明
BLINKGTK_GPU_MODE software / egl / swiftshader software 描画モードの選択。software が推奨・既定。egl は GPU 経路(実験的)、swiftshader は software 相当
BLINKGTK_HEADLESS 1 未設定 headless 動作(実ディスプレイなし・CI 向け)。--headless 付与を制御
BLINKGTK_NO_SANDBOX 1 / 0 未設定 1 = 無条件で無効化。0 = 無条件で有効のまま。未設定 = 自動判定 — /proc/sys/user/max_user_namespaces を読み、0 か読めなければ無効化されます。有効になったかは blink_gtk_is_sandboxed() で問い合わせられます
BLINKGTK_EXTRA_SCHEMES カンマ区切り scheme 名 未設定 独自の URL スキーム (例: ebook) を、https などと同じ扱いの標準スキームとして登録します。独自スキームの読み込み処理 (custom scheme loader) と組み合わせて使います
BLINKGTK_SCROLL_SPEED — — 廃止。設定しても何も変わりません。スクロール量は固定の係数で決まります (2026-09-15 実測)。該当コードは残っていますが、どの出荷物にも入っていません
BLINKGTK_DMABUF_PATH パス 未設定 egl モードの dmabuf デバイスパス指定
BLINKGTK_FRAME_PNG_DIR ディレクトリパス 未設定 フレーム PNG の保存先(検証用途。設定時のみ保存)
BLINKGTK_FRAME_PNG_MAX 整数 0 診断用フレーム PNG の保存枚数。既定 0 = 保存しない。診断が要るときだけ枚数を指定する
BLINKGTK_DISABLE_SITE_ISOLATION 1 未設定 サイトごとのプロセス分離を無効化します。保護を弱めます。 分離は、あるサイトのページが乗っ取られたときに別のサイトのデータを読ませないための境界です。無効にすると複数サイトの文書が同じプロセスに同居します。v1.2.0-build8 から既定で有効で、これは不具合が出たときの逃げ道です
BLINKGTK_PRESENT_POLICY warm / warm-force 未設定 見る人がいない窓に対して、画面へ出す仕事 (合成・キャプチャ・転送) を止めます。組版とラスタは止めないので先読みは保たれます。warm は窓が隠れている間だけ、warm-force は試験専用で常に止めます。復帰時は damage を待たず 1 回無条件でキャプチャするため、古いフレームは残りません。止めている間も、blink_web_view_capture_screenshot_async() などの撮影は成功し、その後も止めたままです (1.2.3-build2 以降。それより前は 2 秒で失敗していました)。1.2.4-build3 からは、software の撮影はほとんどの場合、要求した時点の画面を返し、画面へは出さずに終わることがあります
BLINKGTK_LOG_LEVEL 0 / 1 / 2 0 診断出力の量。0 すべて / 1 大幅に削減 / 2 ほぼ無音。ログが多いと感じたら上げてください
BLINKGTK_DIAG_VERBOSE 1 未設定 毎フレームの診断も出します (既定は抑止)
BLINKGTK_IM_MODULE gtk / GTK の入力モジュール id 未設定 v1.2.3 から。 入力メソッドの選び方。未設定 (または gtk) なら BlinkGTK は何も名指しせず、GTK に決めさせます (Wayland では text-input 経路)。その他の値 (ibus など) はその id を BlinkGTK のビューに名指しします。1.2.2 と同じ動作にするには ibus を指定します。 設定した値は blink_gtk_get_im_module() で問い合わせられます
GTK_IM_MODULE GTK の入力モジュール id — v1.2.3 以降、BLINKGTK_IM_MODULE が未設定なら BlinkGTK の WebView にも適用されます (GTK の通常の選び方に従うため)。BLINKGTK_IM_MODULE で id を名指しした場合は、GTK4 の gtk_im_multicontext_set_context_id() がこの変数より優先されるので、WebView にはこの変数が適用されません。1.2.2 までは BlinkGTK が常に ibus を名指しし、XMODIFIERS から判別してプロセス全体のこの変数を書き換えていました。1.2.3 からは書き換えません
BLINKGTK_A11Y 1 未設定 アクセシビリティを有効にします。 支援技術 (Orca 等) が Web ページの中身を読めるよう、ページの構造を AT-SPI に出します。既定では Chromium がページのアクセシビリティ情報を作らないため、出すものがありません。常時有効にすると全ページでその構築費用がかかるので、必要なときに開く形にしています。指定しなくても、支援技術 (Orca 等) が接続すると自動で開きます (1.2.2-build4 から。アプリの後から支援技術を起動した場合も含む)。1.2.4 からは at-spi2-core 2.61 以降 (Fedora 45 等) でも自動で開き、BLINKGTK_A11Y=1 で起動した後に支援技術を起動した場合も届きます。自動で開かない環境では 1 を指定してください。コマンドライン引数 --force-renderer-accessibility でも同じことができますが、起動経路に依存しない環境変数のほうが確実です
BLINKGTK_UPDATE_CHECK 1 未設定 (オフ) 1.2.4 から。 新しい版が出ていたら、ログに英語と日本語の 2 行 ([BlinkGTK update] A newer version is available: ... / [BlinkGTK update] 新しい版があります: ...) で知らせます。アプリ側から blink_gtk_set_update_check(TRUE) (blink_gtk_init() の前に呼ぶ) でもオンにできます。その場合も利用者が BLINKGTK_UPDATE_CHECK=0 を指定すれば止まります (利用者の指定が優先)。既定はオフ — BlinkGTK は他の製品に組み込まれるので、製品の利用者が知らないうちに外へ通信しないためです。1 のときだけ、起動の 5 秒後に 1 回、配布のリポジトリの版の一覧 (GitHub の API、api.github.com) を読みます。添付ファイルは取得しません。確かめるのは 1 日 1 回までで、結果は $XDG_CACHE_HOME/blinkgtk/update-check に置きます。Windows の版とは取り違えません。通信できないときは何も案内しません (起動は待たせません)
BLINKGTK_WIN_GPU_PATH vulkan 未設定 Windows 専用・試験段階 (BlinkGTK for Windows 1.2.4-build4 から)。 値 vulkan のとき、Chromium の GPU 合成の結果を CPU に読み戻さずに GTK の Vulkan のレンダラーへ渡します。サイトや Windows 版のお知らせで「GPU の経路 P4」と呼んでいるものです (指定する値は vulkan だけです)。既定は無効。Intel Iris Xe の 1 機種でのみ確認。 Linux では使われない

2. エスケープハッチ(既定のまま推奨)

不具合が出て、下の修正が関係していそうなときに、その修正だけを止めて確かめるためのものです。止めて症状が消えた場合は、使っている版と症状を添えてお知らせください。

変数 効果(=0 等を設定した場合) 関連する修正
BLINKGTK_PUMP_LEGACY=1 メインループの回し方を、Wayland の接続を監視する方式 (fd-watcher pump) から以前の方式 (g_idle pump) に戻す(待機中の CPU の使用率が増えます) 1.1.0 の修正: 何も操作していない間も CPU を 1 コア近く使い続けていた問題
BLINKGTK_PUMP_RESCUE=0 メインループを 100ms ごとに必ず起こす仕組み (起床の保証) を無効化 1.1.0 で、下の「白紙のまま固定される問題」の修正と一緒に入ったもの
BLINKGTK_QUEUE_DRAW_TIMER=1 1.2.4 から。16ms ごとの定期の描き直しを、それより前の版と同じく常に動かす。1.2.4 の既定では、静止した頁を描き直し続けないよう、BlinkWebView ではこの描き直しを動かさない (待機中の CPU の使用率が下がる)。=0 で常に止める 1.2.4 の変更: 静止した頁を 16ms ごとに描き直さない
BLINKGTK_T2_AUTO=0 1.2.4 から。拡大率 1 の画面で、ソフトウェアの描画の受け取りを T2 (撮影を使わず、合成の結果を共有メモリで受け取る経路) に自動で切り替えるのをやめ、それより前の版と同じ経路を使う。1.2.4 の既定では拡大率 1 のとき T2 を選び、小さな範囲だけが変わる頁で CPU の使用率が下がる。拡大率 1 以外の画面では T2 を使わず、移ったときも元の経路に戻す。BLINKGTK_USE_MOJO_IPC=0 でも同じ 1.2.4 の変更: 拡大率 1 の画面で T2 を既定にした
BLINKGTK_CAPTURE_DAMAGE_GATE=0 画面が変わっていないときに画面のコピー (キャプチャ) を省く仕組み (capture damage gate) を無効化 1.1.0 の修正: 待機中に CPU を使い続けていた問題
BLINKGTK_FORCE_SINGLE_THREADED=1 renderer を単一スレッド compositing に戻す(描画停止リスクあり)
BLINKGTK_120_INVAL_FALLBACK=0 描き直す範囲が空と計算されたときに補う仕組み (invalidation フォールバック) を無効化 1.1.0 の修正: 文字サイズを大きく変えた直後に、頁が白紙のまま固定される問題
BLINKGTK_EGL_AUTO_FALLBACK=0 GPU 経路が使えないときの software 自動退避を無効化(画面が白いままになります)
BLINKGTK_EGL_AUTO_FALLBACK_MS=<ms> 上記の待ち時間(既定 5000)。短くすると GPU 初期化の遅い機械で誤退避します
BLINKGTK_120_ACT_REDRAW=0 新しい描画結果を有効にしたとき、もう一度描き直させる仕組み (activation 再 damage) を無効化 1.1.0 の修正: 文字サイズを大きく変えた直後に、頁が白紙のまま固定される問題
BLINKGTK_120_CKB_REDRAW=0 まだ描かれていない部分 (checkerboard) が残ったときに描き直させる仕組みを無効化 1.1.0 の修正 (文字サイズを大きく変えた直後に、頁が白紙のまま固定される問題) に対する予備の対策
BLINKGTK_EGL_FRACTIONAL=1 egl モードの分数スケーリングを opt-in(実験的)。1.2.4 から、拡大率 1.25・1.5 の画面で頁が分数の拡大率 (devicePixelRatio 1.25・1.5) で描かれる。それより前の版 (1.2.0-build3〜1.2.3) では、エンジンが自動で付ける拡大率に整数へ切り上げられ、2 で描かれていた 1.1.0 から指定したときだけ有効。1.2.4 の修正で分数のまま描かれる
BLINKGTK_EGL_RESIZE_BRIDGE=0 egl resize ブリッジを無効化
BLINKGTK_RUBY_RESERVE_EM=0.5 段組みの列の切断幅から、ルビの張り出しぶん (0.5em) を差し引く、v1.2.0 までの動作に戻す。差し引くと列に入る量が減り、行がちょうど 1 本入らなくなることがある v1.2.1 の変更: 既定を 0 (差し引かない) にした
BLINKGTK_FRAME_COPY=1 1.2.3-build4 から。 software の描画で、画面へ渡す 1 枚ごとに画素をコピーする従来の動作に戻す (既定はコピーせずに渡す)。表示がおかしいときの切り分け用
BLINKGTK_EGL_FAKE_PRESENTATION=0 1.2.4 から。 egl モードで「画面に出た」の通知を送らない、以前の動作に戻す。戻すと、動く頁を表示し続けたときに renderer とブラウザのメモリが増え続けます (1.2.3 までの動作)。比べるとき用

3b. 開発用デモ (simple_browser) だけのもの — 配布物では使われません

ライブラリも、配布物のサンプル blinkgtk_browser も、この変数を読みません。 BlinkGTK の開発に使っているデモ simple_browser だけが読む変数です。simple_browser は配布物に含めていません。

変数 効果
BLINKGTK_RESTART_ACTIVATION=0 再起動時に activation token を引き継ぐのをやめます(引き継ぐと新しい窓が前面に出ます)
BLINKGTK_RESTART_LINGER_MS=<ms> 再起動を fork + 親の残存で行い、その残存時間を指定します。既定は 0(無効) で、従来どおり execv します
BLINKGTK_DEMO_SELECT_PATH=<id>@<ms>,... 試験専用。起動から指定したミリ秒の時点で、描画経路の一覧の項目 <id> を選びます (例 egl@6000,software@12000)。人が一覧を選んだときと同じ処理を通ります
BLINKGTK_PERMISSION_ALLOW デモが権限要求を自動で許可します。ライブラリ本体は既定で拒否します
BLINKGTK_INSPECTOR_DASH インスペクタのダッシュボードを開きます
BLINKGTK_TEST_SUITE / BLINKGTK_TEST_CAPTURE デモの検証モード
BLINKGTK_DEMO_NO_EBOOK / BLINKGTK_DEMO_NO_JLREQ デモ起動時の EBOOK 設定 / JLReq 組版の適用を止めます
BLINKGTK_MUTTER_REACTIVATE / BLINKGTK_DEBUG_ISSUE_84 窓の前面化まわりの切り分け用
BLINKGTK_CHROMIUM_VERSION 廃止。同梱しない内部デモ専用の変数でした。配布物では使われません
BLINKGTK_AUTO_RESIZE=<回数> デモが窓を指定回数だけ自分でリサイズします (リサイズまわりの検証用)。止める指定ではありません
BLINKGTK_AUTO_FULLSCREEN=<回数> デモが 2.5 秒ごとに全画面を指定回数だけ往復します。大きな一段のサイズ変化を作る検証用

4. 廃止

変数 状態
BLINKGTK_KEEP_GPU_COMPOSITING=1 software 起動でも GPU 合成を無効にしません。描画経路を実行中に切り替えるための前提です。CPU が増えます(手元の測定でアニメーションするページを 20 秒、約 12% 増。その機械・そのページでの比で、上限でも代表値でもありません)。EGL 経路の切替が公開 API になるまでは無保証です
BLINKGTK_ENABLE_THREADED_COMPOSITING 廃止(threaded compositing は既定 ON 化済み。旧名は無効)
