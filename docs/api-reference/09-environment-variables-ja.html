BlinkGTK API リファレンスマニュアル — 第 9 章 環境変数

作成者: BlinkGTK-Readium プロジェクト(consumer/embedder 視点、#121)
対象バージョン: BlinkGTK 1.2.0(Chromium 151 baseline)

正本について: 環境変数の正リスト(3 区分の表・区分の意味)は上流管理の
environment-variables-ja.md(BlinkGTK 環境変数リファレンス)である。
本章はその表を改変せずに取り込み、consumer(embedder)としての実運用例を
追補したものである。表の内容と正本が食い違った場合は正本が正しい
(二重管理を避けるため、本章では表の意味の改変はしない)。

BlinkGTK が解釈する環境変数は 3 区分で定義される。
embedder が依存してよいのは第 1 区分(公開サポート)のみである。

  • 公開サポート — 安定 API。後方互換を維持し、変更時はリリースノートで告知される。
  • エスケープハッチ — 既定 ON の修正・機構を無効化するトラブルシュート用スイッチ。
    通常運用では設定しないこと。問題の切り分けにのみ使用し、恒久設定にしない
    (将来のリリースで予告のうえ削除されることがある)。
  • 内部診断 — 開発・調査用。無保証・サポート対象外で、予告なく変更・削除される。
    embedder が依存してはいけない。

環境変数は Chromium の子プロセス(Renderer/GPU)にも引き継がれる必要があるため、
プロセス起動前(シェル/launcher)で設定すること。起動後の setenv() に頼らない。

9.1 公開サポート環境変数(正本表)

変数 値 既定 説明
BLINKGTK_GPU_MODE software / egl / swiftshader software 描画モードの選択。software が推奨・既定。egl は GPU 経路(実験的)、swiftshader は software 相当
BLINKGTK_HEADLESS 1 未設定 headless 動作(実ディスプレイなし・CI 向け)。--headless 付与を制御
BLINKGTK_NO_SANDBOX 1 未設定 Chromium sandbox を無効化。コンテナ等 sandbox 非対応環境向け
BLINKGTK_EXTRA_SCHEMES カンマ区切り scheme 名 未設定 追加のカスタム URL scheme を standard scheme として登録(例: ebook)。custom scheme loader と併用
BLINKGTK_SCROLL_SPEED 数値(倍率) 1.0 ホイールスクロール速度の倍率
BLINKGTK_DMABUF_PATH パス 未設定 egl モードの dmabuf デバイスパス指定
BLINKGTK_FRAME_PNG_DIR ディレクトリパス 未設定 フレーム PNG の保存先(検証用途。設定時のみ保存)
BLINKGTK_FRAME_PNG_MAX 整数 実装既定 保存するフレーム PNG の最大枚数

実運用ノート(consumer 追補)

以下は EPUB ビューワ(BlinkGTK-Readium)としての実使用例。値の意味は上表(正本)が正。

BLINKGTK_GPU_MODE

1.2.0-build3 より: egl は指定するだけで動きます。以前は GTK4 統合・
手動 viewport・デバイススケール・受け手ウィジェットの構築を利用者側で
行う必要があり、指定しただけでは白画面になっていました。
現在はエンジンが既定で与えます (BLINKGTK_EGL_GTK4_NATIVE /
BLINKGTK_EGL_MANUAL_VIEWPORT / --force-device-scale-factor)。
明示指定があればそちらが優先されます。

# 既定(software)を明示して起動する例
BLINKGTK_GPU_MODE=software ./my-embedder --no-sandbox --no-zygote

当方は縦書き EPUB 本文の表示・スクリーンショット採取とも software 常用で安定
している(第 1 章 1.5(d) 参照)。egl は実験的であり、常用推奨は software。

env と blink_web_view_new_with_gpu_mode() の関係(上流 #123 レビューでの正式見解)

両者は「どちらが優先か」ではなく 適用される層が違う。

  • env はプロセス起動時に読まれる。API を呼んだ時点で browser プロセス側の読み取りは既に完了している
  • new_with_gpu_mode() は内部で setenv(..., overwrite=1) するため、以降に起動する renderer プロセスにのみ反映される
  • 保持先は単一の static であり、per-WebView ではなくプロセス全体に効く(関数名から受ける印象と実体が異なる)

したがって blink_gtk_init() より前に env を設定する方法を正とする。
new_with_gpu_mode() は「プロセス全体のモードを変更し、以降の renderer に効く」ものとして扱う。
併用は非推奨(結果が呼び出し順に依存するため)。

BLINKGTK_HEADLESS

# CI での自動検証(実ディスプレイなし)
BLINKGTK_HEADLESS=1 BLINKGTK_NO_SANDBOX=1 ./my-embedder

CI・自動ハーネス向け。注意: headless で撮った capture PNG は「実ディスプレイの
見たまま」ではない(第 1 章 1.5(e))。表示品質の最終確認は実ディスプレイで行うこと。

BLINKGTK_NO_SANDBOX

BLINKGTK_NO_SANDBOX=1 ./my-embedder

コンテナ等で子プロセスが起動しない場合に使う。当方の実運用はコマンドライン
フラグ --no-sandbox --no-zygote を blink_gtk_init() の argv に渡す形で常用して
おり、env はフラグを渡せない構成(ラッパー経由起動等)での代替になる。いずれも
サンドボックス無効化のセキュリティ含意を理解した上で使うこと。

BLINKGTK_EXTRA_SCHEMES

# ebook:// を standard scheme として登録して EPUB 資源を配信
BLINKGTK_EXTRA_SCHEMES=ebook ./my-embedder

カスタムスキーム上で SPA を動かす場合の要点: ページ内 fetch() / XHR が通るのは
スキームが standard scheme として登録されているときで、未登録だと fetch が失敗
する(当方は ebook:// で Readium SPA を配信し、この壁を上流 Issue #100 として
解決してもらった経緯がある)。

env と register_custom_scheme_full() は排他ではなく「2 段構え」(上流 #123 レビューでの正式見解)

段 担い手 何をするか
① スキームの性質を宣言 本 env(+ビルトイン登録) standard / secure / Service Worker 可 / CORS 有効 の 4 性質をプロセス起動時に一度だけ登録
② スキームの中身を供給 register_custom_scheme_full()(第 4 章) bytes と Content-Type を返すハンドラを登録

②は①で事前登録されたスキームのいずれかに一致している必要がある(実装コメントにも明記)。
したがって両者は併用が必須であって、どちらかで代替できるものではない。

ビルトインで登録済のスキーム: app / blinkgtk / res / resource / ebook
ebook はビルトイン登録済なので BLINKGTK_EXTRA_SCHEMES は不要。
独自スキーム名を使う場合にのみ本 env で追加する(区切りは , ; : のいずれも可)。

本 env はプロセス起動前に設定すること(登録は起動時に一度だけ走るため、
起動後に設定しても効かない)。

BLINKGTK_SCROLL_SPEED

BLINKGTK_SCROLL_SPEED=2.0 ./my-embedder   # ホイールを 2 倍速に

読書アプリではページ送り主体になるため当方は既定のまま。連続スクロール表示を
主にする embedder で調整余地がある。

BLINKGTK_DMABUF_PATH

egl モード専用。software 運用(推奨)では設定不要。当方は egl を常用していない
ため実運用例なし。

BLINKGTK_FRAME_PNG_DIR / BLINKGTK_FRAME_PNG_MAX

# 描画フレームを PNG 連番で採取(検証・退行調査用)
BLINKGTK_FRAME_PNG_DIR=/tmp/frames BLINKGTK_FRAME_PNG_MAX=100 ./my-embedder

描画退行の調査で「どの時点のフレームから壊れたか」を機械的に追える。設定時のみ
保存されるので、常用起動スクリプトには入れないこと(ディスク消費と I/O 負荷)。
MAX を絞って古いフレームの溢れを防ぐ。

9.2 エスケープハッチ(既定のまま推奨)

既定 ON の修正・機構を無効化するトラブルシュート用スイッチ。通常運用では設定
しないこと。問題の切り分けにのみ使用し、恒久設定にしない(将来のリリースで
予告のうえ削除されることがある)。

変数 効果(=0 等を設定した場合) 関連
BLINKGTK_PUMP_LEGACY=1 fd-watcher pump を無効化し旧 g_idle pump へ(idle CPU が増加します) #115
BLINKGTK_PUMP_RESCUE=0 pump 起床保証(100ms heartbeat)を無効化 #120
BLINKGTK_CAPTURE_DAMAGE_GATE=0 capture damage gate(idle 時のフレームコピー抑制)を無効化 #115
BLINKGTK_FORCE_SINGLE_THREADED=1 renderer を単一スレッド compositing に戻す(描画停止リスクあり) CP-1065
BLINKGTK_120_INVAL_FALLBACK=0 invalidation フォールバック(白紙固定の修正)を無効化 #120 fixG
BLINKGTK_120_ACT_REDRAW=0 activation 再 damage(白紙固定の修正)を無効化 #120 fixF
BLINKGTK_120_CKB_REDRAW=0 checkerboard 再 damage(安全網)を無効化 #120 fixE
BLINKGTK_EGL_FRACTIONAL=1 egl モードの分数スケーリングを opt-in(実験的) #117
BLINKGTK_EGL_RESIZE_BRIDGE=0 egl resize ブリッジを無効化 CP-1092
BLINKGTK_RESIZE_FIT=center リサイズ中の旧フレームを中央に置く(既定は上端) #132
BLINKGTK_RESIZE_FIT=stretch リサイズ中の旧フレームを引き伸ばす(build2 までの挙動) #132

consumer 追補: 使いどころは「上流に不具合報告する際の二分探索」のみ。
たとえば表示不具合が出たとき、BLINKGTK_120_*=0 で症状が変わるかを 1 変数ずつ
確認して報告に添えると、上流の切り分けが 1 往復速くなる。切り分けが終わったら
必ず外す(恒久設定にした時点でサポート外構成になる)。

9.5 embedder 側 env との住み分け(consumer 追補)

embedder 自身が独自の環境変数を持つ場合(当方の launcher なら READIUM_* 群)、
BLINKGTK_ プレフィクスと衝突しない自前プレフィクスに統一することを勧める。
利用者から見ると起動シェルに両系統が並ぶため、「どちらのレイヤの knob か」が
名前で判別できることがトラブルシュートの初動を速くする。
