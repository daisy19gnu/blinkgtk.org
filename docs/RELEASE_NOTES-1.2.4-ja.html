BlinkGTK 1.2.4-build1 リリースノート

リリース日: 2026-10-07 / Chromium: 155.0.8059.39 / 言語: 日本語 | English

レンダリングエンジンを Chromium 155 に更新しました。

Fedora 44 のサポートを終了しました

  • Fedora 44 向けの提供は v1.2.3 までです。 v1.2.4 から、RPM は Fedora 45 以降 (glibc 2.44 以上) 向けだけになります。
  • Fedora 44 で dnf のリポジトリを登録している方: そのまま v1.2.3 に留まります。更新でエラーになることはありません。
  • Fedora 45 で dnf のリポジトリを登録している方: 次の 1 行を 1 回だけ実行すると、v1.2.4 以降を受け取れます。
sudo dnf install https://blinkgtk.org/repo/fedora/blinkgtk-release.noarch.rpm

blinkgtk-release はリポジトリの設定 (/etc/yum.repos.d/blinkgtk.repo) と公開鍵だけのパッケージで、Fedora の版ごとのリポジトリを見ます。以前 curl で置いた .repo は blinkgtk.repo.rpmorig として残り、使われません。これからリポジトリの設定を変えるときは、このパッケージの更新でお届けします。

リポジトリを登録せず RPM ファイルを直接インストールする場合も、本体がこのパッケージを必要とします。同じ Release にある blinkgtk-release-*.noarch.rpm を一緒に指定してください (sudo dnf install ./blinkgtk-release-*.noarch.rpm ./blinkgtk-bin-<版>.fc45.x86_64.rpm)。

日本語組版に関わる変更 (Chromium 155)

  • ルビの後の行が上にずれる不具合が直りました。 前の要素に負の margin (疑似要素によるものなど) があると、ルビの注釈の領域が負の値になり、ルビの無い後続の行が上にずれていました (上流の修正)。
  • 段組みの中のルビの注釈の領域を、段の高さをそろえる段組みの中でも次のブロックへ伝えるようになりました (上流の変更)。段組みの縦書きでルビを使う頁では、配置が変わる場合があります。
  • ::first-line の行の高さの計算が、Chromium 153 以前と同じに戻ります。 CSS の仕様が改められたことに合わせた上流の変更です。
  • CSS の margin-trim と text-decoration-skip-spaces が使えます (Chromium 155 で既定で有効になりました)。
  • 圏点をルビと同じ仕組みで配置する変更と、ルビを含む行でのカーソルの上下移動の修正は、Chromium 151 から有効だったものが恒久化されました。挙動は変わりません。

build1 でできるようになったこと

  • 縦書きの行末のぶら下げ (hanging-punctuation: allow-end) が既定で有効です。 縦書きでのずれと、行が組めないときの値の扱いを修正しています。
  • 組版の機能が入っているかを実行時に確かめられます: blink_gtk_has_typesetting_feature() (#153)。blink_gtk_init() の前でも呼べ、"hanging-punctuation:allow-end" で TRUE を返します。返すのは「このライブラリに入っているか」で、--disable-blink-features で切ったかどうかは見ません。
  • 新しい版が出ていたらログで知らせられます (既定はオフ)。BLINKGTK_UPDATE_CHECK=1 か blink_gtk_set_update_check(TRUE) でオンにします。案内は英語と日本語の 2 行で、1 日 1 回までです。
  • Windows (MSVC) 向けに、公開 API の宣言に BLINKGTK_EXPORT を揃えました (#142、blink_gtk_sandbox_init() を除く)。blinkgtk_export.h のコメントを ASCII にしました (blinkgtk_version.h は 1.2.3-build4 から ASCII です)。blink_gtk.h には、日本語の Windows のコンパイラ (/utf-8 なし) で次の行が読み飛ばされる形のコメントはありません (1.2.3 でもありませんでした) (#156)。1.2.4 のヘッダは MSVC では試していません。blink_gtk.h には日本語のコメントがあり警告 C4819 が出るので、/WX を使う場合は /utf-8 を付けてください。

build1 で速くなったこと

  • 拡大率 1 の画面では、ソフトウェアの描画を撮影を使わない経路で受け取るようにしました (blinkgtk-dist #8)。撮影の要求が付かないので、Viz は変わった範囲だけを合成できます (GTK へ渡す画は今も全面です)。小さな範囲だけが変わる頁で CPU の使用率が下がります。部分更新の頁で 16 秒間に使った CPU 時間 (5 回の中央値。ホストのプロセスと子プロセスの全スレッドの合計): Intel i5-10310U の機械で 9.20 → 5.07 秒、Intel i7-8550U の機械で 15.74 → 9.19 秒 (どちらも weston headless)。この値は Chromium 154 の開発版で、経路を BLINKGTK_USE_MOJO_IPC=1 で指定して測ったもので、1.2.4-build1 と自動の選択では測り直していません。拡大率 1 以外の画面では使わず、移ったときは以前の経路に戻します。BLINKGTK_T2_AUTO=0 で以前の経路に戻せます。
  • BlinkWebView では、静止した頁を 16ms ごとに描き直し続けないようにしました (blinkgtk-dist #8)。待機中の CPU の使用率が下がります (16 秒間に使った CPU 時間、Intel i5-10310U の機械で 2.04 → 0.48 秒、5 回の中央値。Chromium 154 の開発版で測った値)。BLINKGTK_QUEUE_DRAW_TIMER=1 で以前の動作に戻せます。

build1 で修正したこと

  • EGL で描き続けるとメモリが増え続けていました。 renderer +5.6 → +1.6 MB/分、ブラウザ +1.8 → 0 MB/分。
  • at-spi2-core 2.61 (Fedora 45 の 2.61.90 で確認) で、スクリーンリーダーを起動してもアクセシビリティツリーが出ませんでした。 2.61 で検知に使っていたプロパティが無くなったためで、新しい検知の方法に合わせました。環境変数を付けなくても、支援技術を起動すると有効になります。
  • BLINKGTK_A11Y=1 で起動した後に支援技術を起動した場合、アクセシビリティツリーが届きませんでした (#145)。この場合も届くようにしました。
  • XML 文書 (DAISY 3 の DTBook など) で、blink_web_view_inject_user_stylesheet() と選択の禁止が当たりませんでした (<?xml-stylesheet?> を持つ文書)。
  • 表示の方針を WARM から ACTIVE に戻したとき、止めている間に読み込んだ文書が 0.8〜1.2 秒出ませんでした。 修正後は 50〜53 ms です。
  • EGL で BLINKGTK_EGL_FRACTIONAL=1 を指定しても、拡大率 1.25・1.5 の画面で頁が 2 で描かれていました (#117)。指定があるときは分数のまま描きます。
  • T2 (BLINKGTK_USE_MOJO_IPC=1) で 2 件: window.open() でアプリが作った 2 つ目のビューが空になり、その画が最初のビューに出ていました。画面へ出さない宣言 (WARM / IDLE) の下でも画面への受け渡しが止まりませんでした。

build1 で挙動が変わるもの

  • 日本語組版に関わるものは上の「日本語組版に関わる変更」にまとめました。
  • GTK が Wayland 以外 (GDK_BACKEND=x11 など) で動いたとき、警告を 1 件出します。 BlinkGTK は Wayland だけを対象にしており、この場合イベントの回し方が CPU を 1 コア使い続ける方式になります。動作は変えていません。
