BlinkGTK 1.2.4-build4 リリースノート

リリース日: 2026-10-14 / Chromium: 155.0.8059.39 / 言語: 日本語 | English

レンダリングエンジンを Chromium 155 に更新しました。

前の版 (1.2.3) から上げる方へ

使い方に当たる行を確かめてください。詳しい説明は各行のリンク先にあります。

この表は Linux 版のものです。BlinkGTK for Windows では組版の機能 (ぶら下げ・割注) が入っておらず、動作しません。Windows の方は Windows 版の「前の版から上げる方」 を確かめてください。MSVC で /WX を使う場合は、blink_gtk.h の日本語のコメントで警告 C4819 が出るので /utf-8 を付けてください (詳細)。

Fedora 44 のサポートを終了しました

  • Fedora 44 向けの提供は v1.2.3 までです。 v1.2.4 から、RPM は Fedora 45 以降 (glibc 2.44 以上) 向けだけになります。
  • Fedora 44 で dnf のリポジトリを登録している方: そのまま v1.2.3 に留まります。更新でエラーになることはありません。
  • Fedora 45 で dnf のリポジトリを登録している方: 次の 1 行を 1 回だけ実行すると、v1.2.4 以降を受け取れます。
sudo dnf install https://blinkgtk.org/repo/fedora/blinkgtk-release.noarch.rpm

blinkgtk-release はリポジトリの設定 (/etc/yum.repos.d/blinkgtk.repo) と公開鍵だけのパッケージで、Fedora の版ごとのリポジトリを見ます。以前 curl で置いた .repo は blinkgtk.repo.rpmorig として残り、使われません。これからリポジトリの設定を変えるときは、このパッケージの更新でお届けします。

リポジトリを登録せず RPM ファイルを直接インストールする場合も、本体がこのパッケージを必要とします。同じ Release にある blinkgtk-release-*.noarch.rpm を一緒に指定してください。例: sudo dnf install ./blinkgtk-release-*.noarch.rpm ./blinkgtk-bin-<版>.fc45.x86_64.rpm

日本語組版に関わる変更 (Chromium 155)

  • ルビの後の行が上にずれる不具合が修正されました。 要素自身・前の兄弟・子の負の margin (疑似要素によるものなど) を相殺した結果が負になると、ルビの注釈の領域が負の値になることがあり、そのときルビの無い後続の行が上にずれていました (上流の修正)。
  • 段組みの中のルビの注釈の領域についての上流の変更は、試験段階のフラグ (AnnotationSpaceForMultiCol) の下だけに入りました。 既定では配置は変わりません。
  • ::first-line の行の高さの計算が、フラグ FirstLineTextMetrics が入る前の計算 (古い Blink・WebKit と同じ) に戻ります。 Chromium 154 まで既定で有効だった計算を外す、CSS の仕様が改められたことに合わせた上流の変更です。
  • CSS の margin-trim と text-decoration-skip-spaces が使えます (Chromium 155 で既定で有効になりました)。
  • 圏点をルビと同じ仕組みで配置する変更と、ルビを含む行でのカーソルの上下移動の修正は、Chromium 151 から有効だったものが恒久化されました。挙動は変わりません。

build4 で修正したこと

  • 頁を移った後に本文をクリックすると、アプリが異常終了することがありました。 頁を移ると描画の部品 (RenderWidgetHostView) が作り直されますが、前の部品が文字入力の管理 (TextInputManager) の通知先に残っていて、本文のクリックで選択が変わったときに、解放済みの部品を呼んでいました。本文に user-select: none を当てている頁では、クリックで選択が変わらないので、クリックでは起きませんでした。
  • 支援技術を有効にして頁を移ると、アプリが応答しなくなることがありました。 前の文書の部品が破棄された後も、支援技術への橋渡しが、破棄済みのアクセシビリティツリーを指したままでした。支援技術 (AT-SPI) が前の文書の項目を問い合わせると、メインスレッドが戻らなくなっていました。支援技術を使わない場合は起きませんでした。
  • 同梱の INSTALL と README が、DEB のファイル名を誤って案内していました (libblinkgtk-0.1-0_<版>_amd64.deb と書いていたが、正しくは ..._<版>-1_amd64.deb)。案内どおりに打つと、ファイルが見つからずに失敗していました。

build3 でできるようになったこと・変わったこと

  • 割注を組めるようになりました (1 行に収まるもの)。 インライン要素に -blinkgtk-warichu: auto を付けると、本文の 1 行の中で 2 列の小さな字に組みます。割注の字の大きさ (font-size: 0.5em など) と括弧は、頁の側で指定します。行をまたぐ割注はまだ組めません。使えるかどうかは blink_gtk_has_typesetting_feature("warichu:single-line") で確かめられます。書き方は試験段階です。 利用者からの意見で、次の版で変えることがあります。
    • -blinkgtk-warichu: auto を付けた要素では、傍点 (要素自身に指定したものも含む) と、祖先から伝わる下線などの線を描きません。要素自身に指定した text-decoration は描きます。下の条件で割注にならなかった場合も同じです。
    • 次の場合は割注にせず、いつもどおりに組みます。
      • 中身が文字だけでない (<br>・縦中横・画像・入れ子の要素を含む)、または中身が空
      • 改行を保つ white-space、または hyphens: auto
      • 右から左の文字を含む
      • 要素に margin・border・padding がある
      • ルビの中にある、または SVG の文字の要素 (<tspan> など) である
      • 本文の空の行にも収まらない長さ
    • -blinkgtk-warichu: auto を付けた要素を含む段落では、text-wrap: pretty は反映されません (割注にならなかった場合も)。
  • 非同期の撮影 (blink_web_view_capture_screenshot_async()) は、software では、ほとんどの場合、要求した時点の画面を返すようになりました。 要求の後に画面へ渡される次のフレームが先に届いたときは、そのフレームになります。これまでは次のフレームを待って撮っていたので、要求の直後に頁が変わる場面では、写る内容がこれまでと変わります。画面への受け渡しを止めている間 (提示ポリシー) の撮影は、画面へ出さずに終わることがあります。EGL と同期版で撮れる内容は変わりません。
  • 組み込み AI の API (LanguageModel・Summarizer・Translator・LanguageDetector) は、どれも「使えない」と答えます。 BlinkGTK は端末内のモデルを持ちません。これまでは LanguageModel・Summarizer・LanguageDetector の availability() が "downloadable" を返し、Translator は応答が返りませんでした。

build3 で修正したこと

  • software の非同期の撮影で、静止した頁を撮ると、2 秒で失敗を返すのに、要求したパスにファイルが残っていました。 1.2.4 の既定 (拡大率 1 では描画結果を mojo の共有メモリで受け取る) で起きていました。ファイルを書く仕組みを 1 つにし、時間切れのときは書かないようにしました (仕組みによるもので、時間切れの回は作れず測っていません)。撮影の画像を待つ時間に上限は無いので、機械の負荷が高いときは時間切れになり得ます。EGL では、次のフレームが 2 秒以内に来なければ、これまでどおり時間切れになります。同期版 blink_web_view_capture_screenshot() は変えていません (失敗してもファイルが残ることがあります)。
  • EGL で撮影した画像の赤と青が入れ替わっていました。
  • EGL で、撮影の完了の通知の中で窓を閉じると、アプリが異常終了していました。
  • 白い背景の頁で、実行中の描画経路の切替 (BlinkShift) が、描けていても必ず元に戻っていました (黒い背景の頁も同じ判定でした)。切替の前に表示していた画面と比べて判定するようにしました。黒い背景の頁で egl から切り替えるときは、描画を確かめられないので、これまでどおり元に戻ります。
  • C API リファレンスの BlinkScreenshotCallback の型が、実際のヘッダと違っていました (ヘッダに無い引数 web_view が先頭に書かれていた)。記載どおりに書くとコンパイルで止まります。正しくは (gboolean success, const char* filename, gpointer user_data) です。

build2 で修正したこと

  • 新しい版の案内 (BLINKGTK_UPDATE_CHECK=1 か blink_gtk_set_update_check(TRUE)、既定はオフ) が、必ず失敗していました。 配布のリポジトリの版の一覧の応答 (2026-10-11 に 934,807 バイト) が受け取りの上限 256 KB を超え、ログに check failed (net_error=-12) を 1 行出して諦めていました。上限を 4 MiB にしました。案内を有効にしていない場合 (既定) は、build1 と動作は変わりません。

build1 でできるようになったこと

  • 行末のぶら下げ (hanging-punctuation: allow-end) が既定で有効です。 上流で作業中の CL 8367064 を取り込み、縦組で inline 軸の border や padding がある要素でもぶら下がっていた件と、行が組めない経路で renderer が異常終了していた件を当方で修正しています。
  • 組版の機能が入っているかを実行時に確かめられます: blink_gtk_has_typesetting_feature()。blink_gtk_init() の前でも呼べ、"hanging-punctuation:allow-end" で TRUE を返します。返すのは「このライブラリに入っているか」で、--disable-blink-features で切ったかどうかは見ません。
  • 新しい版が出ていたらログで知らせられます (既定はオフ)。BLINKGTK_UPDATE_CHECK=1 か blink_gtk_set_update_check(TRUE) でオンにします。案内は英語と日本語の 2 行で、1 日 1 回までです。
  • Windows (MSVC) 向けに、公開 API の宣言に BLINKGTK_EXPORT を揃えました (blink_gtk_sandbox_init() を除く)。blinkgtk_export.h のコメントを ASCII にしました (blinkgtk_version.h は 1.2.3-build4 から ASCII です)。blink_gtk.h には、日本語の Windows のコンパイラ (/utf-8 なし) で次の行が読み飛ばされる形のコメントはありません (1.2.3 でもありませんでした)。1.2.4 のヘッダは MSVC では試していません。blink_gtk.h には日本語のコメントがあり警告 C4819 が出るので、/WX を使う場合は /utf-8 を付けてください。

build1 で速くなったこと

  • 拡大率 1 の画面では、ソフトウェアの描画を撮影を使わない経路で受け取るようにしました。撮影の要求と、そのための画素の読み出しが無くなります。変わった範囲だけを合成する形は、見開きの片ページが空白のまま残る不具合 を防ぐ修正が範囲を毎回全面にするため、1.2.4 ではまだ入っていません。小さな範囲だけが変わる頁で CPU の使用率が下がります。部分更新の頁で 16 秒間に使った CPU 時間 (5 回の中央値。ホストのプロセスと子プロセスの全スレッドの合計): Intel i5-10310U の機械で 9.20 → 5.07 秒、Intel i7-8550U の機械で 15.74 → 9.19 秒 (どちらも weston headless)。この値は Chromium 154 の上で作った公開前の BlinkGTK で、経路を BLINKGTK_USE_MOJO_IPC=1 で指定して測ったもので、1.2.4-build1 と自動の選択では測り直していません。拡大率 1 以外の画面では使わず、移ったときは以前の経路に戻します。BLINKGTK_T2_AUTO=0 で以前の経路に戻せます。
  • BlinkWebView では、静止した頁を 16ms ごとに描き直し続けないようにしました。待機中の CPU の使用率が下がります (16 秒間に使った CPU 時間、Intel i5-10310U の機械で 2.04 → 0.48 秒、5 回の中央値。Chromium 154 の上で作った公開前の BlinkGTK で測った値)。BLINKGTK_QUEUE_DRAW_TIMER=1 で以前の動作に戻せます。

build1 で修正したこと

  • EGL で描き続けるとメモリが増え続けていました。 renderer +5.6 → +1.6 MB/分、ブラウザ +1.8 → 0 MB/分 (Chromium 154 の上で作った公開前の BlinkGTK、Canvas 2D の頁で、同じ仕組みを試験用の切り替えで有効にして測った値)。1.2.4-build1 でも、検査 (renderer 3,000 KB/分以下、ブラウザ 500 KB/分以下) が PASS しています。
  • at-spi2-core 2.61 (Fedora 45 の 2.61.90 で確認) で、環境変数を付けずに起動したとき、スクリーンリーダーを起動してもアクセシビリティツリーが出ませんでした。 2.61 で検知に使っていたプロパティが無くなったためで、新しい検知の方法に合わせました。環境変数を付けなくても、支援技術を起動すると有効になります。
  • BLINKGTK_A11Y=1 で起動した後に支援技術を起動した場合、アクセシビリティツリーが届きませんでした。この場合も届くようにしました。
  • XML 文書 (DAISY 3 の DTBook など) で、blink_web_view_inject_user_stylesheet() と選択の禁止が当たりませんでした (<?xml-stylesheet?> を持つ文書)。
  • 表示の方針を WARM から ACTIVE に戻したとき、止めている間に読み込んだ文書が 0.8〜1.2 秒出ませんでした。 修正後は 50〜53 ms です。
  • EGL で BLINKGTK_EGL_FRACTIONAL=1 を指定しても、拡大率 1.25・1.5 の画面で頁が 2 で描かれていました。指定があるときは分数のまま描きます。
  • 撮影を使わない経路 (BLINKGTK_USE_MOJO_IPC=1。拡大率 1 では既定) で 2 件: window.open() でアプリが作った 2 つ目のビューが空になり、その画が最初のビューに出ていました。画面へ出さない宣言 (WARM / IDLE) の下でも画面への受け渡しが止まりませんでした。

build1 で挙動が変わるもの

  • 日本語組版に関わるものは上の「日本語組版に関わる変更」にまとめました。
  • text-decoration-skip-spaces の既定の値 (start end) が働くようになり、行頭と行末の空白 (全角スペースを含む) には下線などの装飾が引かれなくなります。 例えば段落の頭の字下げを全角スペースで入れた文章に text-decoration を掛けると、その空白の部分に線が引かれません。コードを読んでの判断で、描画は測っていません。以前の描画にするには text-decoration-skip-spaces: none を指定します。
  • GTK が Wayland 以外 (GDK_BACKEND=x11 など) で動いたとき、警告を 1 件出します。 BlinkGTK は Wayland だけを対象にしており、この場合イベントの回し方が CPU を 1 コア使い続ける方式になります。動作は変えていません。
