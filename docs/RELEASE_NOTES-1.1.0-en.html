BlinkGTK 1.1.0-build5 Release Notes

Date: 2026-07-29
Chromium: 150.0.7871.46 (stable)
Status: Development build (1.1.0-dev). This distribution includes verification use.

New Distribution Layout (WebKitGTK parity)

From this version, BlinkGTK ships as three split packages like WebKitGTK
(binary-only, GitHub Releases):

  • runtime (blinkgtk-bin / libblinkgtk-0.1-0): Shared library + Chromium runtime
    (private dir /usr/lib64/blinkgtk-0.1/) + resources. Required to run apps.
  • devel (blinkgtk-bin-devel / libblinkgtk-0.1-dev): Headers + blinkgtk-0.1.pc +
    .so symlink. Required to build against it.
  • gir (blinkgtk-bin-gir): GObject Introspection typelib (for Python / GJS).

The shared library SONAME is now versioned to libblinkgtk-0.1.so.0. Each release ships
THIRD_PARTY_NOTICES.html (third-party license credits) and SHA256SUMS.

Highlights

  • Chromium 150 baseline: Migrated to Chromium 150.0.7871.46 (stable). V8 snapshot
    integrity, render smoke, and on-device vertical rendering (including the EGL path) verified.
  • Vertical multicol column-break fix (Issue #110): For CSS multicol +
    writing-mode: vertical-rl (orthogonal root), lines crossing a column boundary were
    clipped into the adjacent column. This is fixed so column advance is "line-moves-whole".
    Implemented as the Blink RuntimeEnabledFeature CJKVerticalColumnFragmentation,
    enabled with --enable-blink-features=CJKVerticalColumnFragmentation (off by default).
  • Input fixes:
    • Wheel coordinate fix (Issue #112): When the pointer was not at the viewport center,
      wheel-event coordinates were pinned to the center, making off-center UI unscrollable. Fixed.
    • Scrollbar drag: Dragging the scrollbar thumb did not scroll. Fixed.
    • Input after top-level navigation (Issue #114): On top-level navigation (e.g. reader
      <-> library) where the RenderWidgetHostView is recreated, mouse input kept being forwarded
      to the destroyed old host (requiring a restart). Fixed.
  • GObject type system: GType registration for four enum/flag types (LoadEvent / LoadError /
    GpuMode / ContentPolicy), property notifications (notify::), and uri-changed signal
    emission on real navigation. Verified from PyGObject / GJS.

Changes in build5 (2026-07-29)

The bundled sample has been replaced

The bundle now contains a single minimal sample, blinkgtk_browser, which does nothing but
display https://google.com/. The development browser shipped previously contained a great deal of
development-only machinery (render-path switching, typesetting overlays, and so on) and was too large
to serve as an example of how to embed BlinkGTK.

examples/ now contains just three files: blinkgtk_browser.c (105 lines), Makefile, and
README.md. make alone builds it.

Fixes

  • Fixed blink_gtk_set_resources_path() not taking effect for some resources. The ICU data and the
    V8 snapshots honoured it, but the resource pack (content_shell.pak) was still resolved relative
    to the directory containing the executable, so an application placed away from the resources
    failed to start with Check failed: data_pack->LoadFromPath(path).
  • Fixed the bundled sample executable having the build machine's absolute path embedded as an
    rpath.

Documentation

  • For GTK4 itself, the documentation now points to the official GTK4 documentation
    (docs.gtk.org). BlinkGTK is a library that provides one GTK4 widget. The main loop is the one
    exception: you must use blink_gtk_run_main_loop(), since GTK's g_application_run() leaves the
    window blank.
  • Removed examples of command-line options that the bundled sample does not have from the settings
    API documentation, replacing them with API usage.

Changes in build4 (2026-07-29)

build4 restores consistency between the bundled documentation and the bundled binary.

Documentation corrections (the point of this build)

The documentation bundled with build2 and build3 referenced 20 APIs that do not exist in the
bundled binary. Following it as written would not build. The affected documents were
settings-api, c-api-reference, navigation-api, signals-api, the settings and events
tutorials, and ENGINE_COMPARISON_DETAILED.

This build corrects them as follows:

  • Corrected to the real names where the documentation disagreed with the implementation
    (for example blink_web_view_set_enable_javascript -> blink_web_view_set_javascript_enabled,
    and blink_web_view_set_auto_load_images -> blink_web_view_set_images_enabled)
  • Implemented what was missing: user-agent get/set and cookie setting (see below)
  • Withdrew documentation for unimplemented features: blink-settings-quickstart (an INI-based
    settings-file API) has no implementation and has been removed from the bundle. The accessibility
    API documentation has been withdrawn for the same reason. Both will be provided again once
    implemented.

A gate that extracts the distributed artifact itself and mechanically verifies that every API named
in the bundled documentation exists in the bundled binary is now a precondition for publishing.

New APIs

  • blink_web_view_set_user_agent() / blink_web_view_get_user_agent() - override and read the
    User-Agent
  • blink_web_view_set_cookie() - set a cookie (asynchronous; the result arrives via a callback)
  • The permission-request signal and BlinkPermissionRequest - lets the application decide on
    permission requests such as geolocation and notifications. The default is to deny: if the
    signal is not handled, every request is denied. Use
    blink_permission_request_get_type_name() to obtain the request type and
    blink_permission_request_allow() / blink_permission_request_deny() to respond.

Changes to the bundle

  • api_check.c and api_tester.c, which used to accompany examples/, are no longer bundled:
    they are old checking programs with no maintained source in the repository.
  • examples/Makefile has been replaced with a concise pkg-config based one. The Makefile bundled
    previously was generated by autotools, contained absolute paths from the build machine, and did
    not work as-is on the user's system.

Distribution

build3 replaced only the RPMs. In build4, the tarballs, RPMs, and DEBs are all regenerated as
build4.

Changes in build2 (2026-07-21)

build2 is the first public release of the BlinkGTK v1.1 series (build1 was internal verification only and was not publicly released).

An interim rebuild from build1 (2026-07-07) on the same Chromium baseline, adding:

  • Idle CPU consumption eliminated (Issue #115): The main loop now uses fd-based
    watching and the capture damage gate is enabled by default, reducing steady-state
    CPU usage (previously ~1 core) to near zero. Troubleshooting switches:
    BLINKGTK_PUMP_LEGACY=1 / BLINKGTK_CAPTURE_DAMAGE_GATE=0.
  • Root fix for persistent blank pages after large font-size changes (Issue #120):
    The root cause — during heavy reflow, a recording update could be computed with an
    empty invalidation region, leaving stale blank tiles valid forever — was identified
    and fixed with a two-part change (invalidation fallback + activation-time re-damage),
    both enabled by default. A deterministic fault-injection regression harness is
    included; the fix is machine-verified. Switches: BLINKGTK_120_INVAL_FALLBACK=0 /
    BLINKGTK_120_ACT_REDRAW=0.
  • Main-loop wakeup guarantee (with Issue #120): A 100 ms wakeup heartbeat bounds
    posted-task latency (measured idle overhead below +0.5%). Switch: BLINKGTK_PUMP_RESCUE=0.
  • EGL fractional scaling made opt-in (Issue #117): The default returns to integer
    scaling; experimental fractional support now requires explicit BLINKGTK_EGL_FRACTIONAL=1.
  • Environment variables reference: The canonical list of publicly supported
    environment variables (environment-variables-{ja,en}.md) is now bundled.
  • Diagnostic infrastructure (frame inspection, fault injection, etc.) ships behind
    environment-variable gates (disabled by default) and does not affect normal operation.

Compatibility

  • Consumers must link the PartitionAlloc allocator shim directly (the bundled pkg-config
    blinkgtk-0.1.pc handles this; Issue #90).
  • No breaking changes to the C API.
  • With the versioned SONAME (libblinkgtk-0.1.so.0), newly-linked consumers get a versioned
    dependency; building via the devel package's pkg-config resolves it automatically.

Known Limitations

  • CJKVerticalColumnFragmentation is a staged implementation assuming column-width 600px /
    column-gap 0 / orthogonal-root border-padding 0 (experimental, off by default).
  • For tarball (FHS) runs, resolve the private dir (/usr/lib64/blinkgtk-0.1/) via the runtime
    ld.so.conf.d fragment or LD_LIBRARY_PATH.
  • Idle CPU consumption (Issue #115) is under continued investigation.
