BlinkGTK for Windows — Getting started

BlinkGTK for Windows lets you use Chromium's rendering engine (Blink) as a GTK4 widget, from C.
Unpack the ZIP and run bin\blinkgtk_browser.exe and it works at once (no administrator rights needed).
The API is nearly the same as the Linux version, so you can use the same code on both operating systems (the differences are collected in "Differences from the Linux version" below).

This page describes v1.2.5-build1 (Chromium 156.0.8078.47). We checked on Windows 11 Pro (build 26300), on 2026-10-23, that it unpacks and runs.

Who it is for

  • You want to embed the same rendering engine as Chromium in a GTK4 app. BlinkGTK works as a GtkWidget and is driven by a C API.

  • You are considering moving from WebView2, CEF or Electron. WebView2 is a Windows-only component (Win32, WinUI, WPF and similar), so the code is not shared with Linux. CEF has C and C++ APIs and also runs on Linux, and Electron is a framework for JavaScript apps. What is different about BlinkGTK is that you can use it from C as a GTK4 widget. It is an option when you write a GTK4 app in C and want to use the same code on Linux and Windows. It is not a drop-in replacement for an existing app.

  • You are considering moving from WebKitGTK. BlinkGTK has APIs with names similar to WebKitGTK's. We have not checked compatibility down to the fine details of behavior. The names correspond as follows.

    Purpose WebKitGTK BlinkGTK
    Create a view webkit_web_view_new() blink_web_view_new()
    Load a URL webkit_web_view_load_uri() blink_web_view_load_uri()
    Load an HTML string webkit_web_view_load_html() blink_web_view_load_html()
    Loading notification load-changed signal a load-changed signal with the same name. The order of the values differs (see the note below)

    Note: do not reuse the numeric values of load-changed. In BlinkGTK, BLINK_LOAD_STARTED=0, BLINK_LOAD_COMMITTED=1, BLINK_LOAD_FINISHED=2 and BLINK_LOAD_REDIRECTED=3 (BlinkLoadEvent in the header blink_gtk.h). In WebKitGTK, REDIRECTED is 1 and COMMITTED and FINISHED are each one higher, so reusing the numbers gives wrong results. Always compare with the BLINK_LOAD_* names. BLINK_LOAD_REDIRECTED is reserved and is not emitted at present.

  • You want to try Japanese vertical text and typesetting. There is an experimental adjustment for vertical text (see Differences from the Linux version). In this version on Windows, hanging punctuation (typesetting that lets punctuation hang past the end of a line) and one-line warichu (inline cutting notes: small notes set in two lines inside a line) work. Warichu that spans lines does not exist yet, even in the Linux version.

Run it

1. Download and unpack

Get the ZIP files from the v1.2.5-build1-windows release of blinkgtk-dist.

File Use
blinkgtk-1.2.5-build1-windows-x64.zip To run it (portable). Start with this one
blinkgtk-devel-1.2.5-build1-windows-x64.zip To embed it (headers and libraries; see Embedding it in your app)
SHA256SUMS To check the ZIPs. Compare it with the output of certutil -hashfile <ZIP> SHA256

Unpack the portable ZIP anywhere. It includes the GTK4 and VC++ runtime DLLs, so there is nothing else to install. There is no installer (MSI) yet.

Unpacking gives three folders: bin (the executables and DLLs), docs (documentation) and share (GTK4 data).

2. A warning may appear the first time

This package is not code-signed. If you download it with a browser and run it, Microsoft Defender SmartScreen may show a warning. Follow the prompt to continue (in general, choose "More info" in the warning and then "Run anyway"; we have not captured the actual screen for this release).

The first start right after unpacking can be slow. Microsoft Defender scans the newly written files (there are about 590 DLLs). From the second start on, it is fast. In our check (Intel Core i5-1140G7, default Defender settings, 2026-10-23), the first start right after unpacking took about 11 seconds until the window appeared, and the later starts took about 0.9 seconds. The time varies with the machine and the Defender settings. It will start if you wait, so please wait.

If you use a Windows 11 Dev Drive (a volume for developers) for your work, unpacking onto the Dev Drive makes even the first start fast. On a Dev Drive, Defender runs in "performance mode" and scans files after they are opened (Defender protection stays on). In our check (same machine), the window appeared in about 3 seconds. See Microsoft's description for how to set up a Dev Drive.

3. Run

In File Explorer, open the bin folder of the unpacked folder and double-click blinkgtk_browser.exe. Without an argument it opens https://google.com/ (an internet connection is needed).

To open a page of your choice, use a Command Prompt (search for "cmd" in the Start menu), move to the bin folder of the unpacked folder, and run:

cd /d "C:\BlinkGTK\blinkgtk-1.2.5-build1-windows-x64\bin"
blinkgtk_browser.exe https://example.com/

The C:\BlinkGTK\... on the first line is an example. Replace it with the actual path where you unpacked it (you can copy the path from the File Explorer address bar). If you paste < and > as they are, the Command Prompt treats them as symbols and fails.

With a URL argument it opens that page.
blinkgtk_browser is a minimal sample that shows only what you need to embed BlinkGTK.

Check that it works

  • If a web page appears in the window, it works.

  • The executable tells you the version you have. Trust this rather than the numbers on the site or in the documents.

> blinkgtk_browser.exe --version
BlinkGTK 1.2.5-build1 (Chromium 156.0.8078.47)
  • If nothing appears, the window stays white, or it exits at once, see If something goes wrong.

Embedding it in your app

The devel ZIP (blinkgtk-devel-1.2.5-build1-windows-x64.zip) contains the public API headers, the import libraries and the GTK4 development files.

  • What you need to build: Visual Studio Build Tools (we checked 2026) with the "Desktop development with C++" workload, and the Windows SDK. If you do not have a build environment yet, section 0 of the bundled docs\building-with-blinkgtk-en.md explains how to install it, with screenshots. You do not need an environment to build Chromium.

    The Modify screen of Visual Studio Installer (Japanese UI). What you use to build apps is "Desktop development with C++" in the list on the left (ticked in this screenshot). "Desktop development with C++" under "Installation details" on the right is collapsed in this screenshot. Expand it and check that the Windows SDK is ticked. If you select something that was missing, let the installation run to the end. After installing, confirm that cl works by following "Check that it works" in section 0 of the bundled docs\building-with-blinkgtk-en.md. This screenshot was taken on a machine that already had it installed.

  • Compiler options: /MD /DCOMPONENT_BUILD. On Japanese Windows with MSVC, add /utf-8 too (otherwise the Japanese comments in the headers cause warning C4819).

  • The full procedure is in the bundled docs\building-with-blinkgtk-en.md (Japanese: docs\building-with-blinkgtk-ja.md). The devel ZIP contains the source of a minimal app and a batch file that builds it, in examples\.

  • The GPU document and the environment-variable document are in Japanese only (there are no English versions yet).

Three things to note.

  1. Do not write your own forward declarations of the public API (Windows only). The headers declare it with __declspec(dllimport); a declaration without it in the same translation unit makes clang warn. Use only the headers.
  2. Free return values that the caller owns with g_free() (for example blink_handoff_meta_serialize()). This has been the rule since 1.2.3-build2.
  3. To use the sandbox, link the static library lib\blinkgtk_sandbox.lib and call blink_gtk_sandbox_init() (Windows only; it cannot be called on Linux, so wrap it in #ifdef G_OS_WIN32 when you share code between the two).

The public API has 154 entry points. Of these 154, the only difference from Linux is one entry point: blink_web_view_attach_to_external_surface (Wayland only) is not on Windows (blink_gtk_sandbox_init() above is Windows-only and is not counted in that number).
We have called 66 of them and confirmed they work. How they are counted, and how to list the ones not yet called, is in §0 of the bundled docs\api-windows-notes-en.md.

Upgrading from an earlier version

The steps are the same from any version.

  1. Unpack the new ZIP into a separate folder and try it; if it is fine, replace the old folder.
  2. If you embed BlinkGTK in your own app, rebuild it with the headers and libraries from the new devel ZIP (compatibility with the previous blinkgtk.dll was not checked).

Notes for each version:

From 1.2.4-build4 to 1.2.5-build1:

  • Chromium moved from 155 to 156 (156.0.8078.47). Compare how vertical text and typesetting look on your own pages.
  • Hanging punctuation and one-line warichu now work. blink_gtk_has_typesetting_feature() returns TRUE for both "hanging-punctuation:allow-end" and "warichu:single-line" (we checked that the answers match the actual behavior). If you wrote your own fallback on the assumption of FALSE, review it.
  • The Linux 1.2.5 changes are included: the load-failed error number is passed as an integer (int), is-loading returns to False when loading ends, set_user_agent() also applies to pages opened with load_uri() and to reload(), and the zoom level (set_zoom_level()) is a factor (1.0 = 100%). We have not checked the behavior of these on Windows.
  • The public API did not change (still 154 entry points).

From 1.2.4-build2 to 1.2.4-build4:

  • The public API did not change (still 154 entry points; the header declarations are the same, only the comments changed).
  • If you decide based on blink_gtk_has_typesetting_feature(): the Windows 1.2.4-build2 returned TRUE for "hanging-punctuation:allow-end", which was wrong; the Windows engine does not include hanging punctuation and it does not work. This version returns FALSE for both names (allow-end and warichu:single-line). Do not decide with CSS.supports or computed values (they return true even where the typesetting is not included).
  • The screenshot API (blink_web_view_capture_screenshot_async() and similar): in Linux 1.2.4-build3, a screenshot on the software path changed to return the content at the time of the request. This change is included, but we have not checked it on Windows.
  • GPU path: it is off by default, so you need to do nothing (see The experimental GPU path).
  • The bundled GTK changed: gtk-4-1.dll is now a Vulkan-enabled build (about 1 MB larger). The default path, without the environment variable, does not change.

From 1.2.3 or earlier: use the steps above as they are. The first Windows 1.2.4 is 1.2.4-build2 (Chromium moved from 154 to 155). Up to 1.2.3-build4, a process could crash when an internal assumption failed. From 1.2.4 that check is disabled in the build.

Differences from the Linux version

Linux Windows
Install RPM / DEB / tarball ZIP (MSI later)
GTK4 OS package Bundled
How rendered output is handed to GTK software / EGL software by default. There is no EGL on Windows. An experimental GPU path can be selected with an environment variable (below)
blink_web_view_attach_to_external_surface Yes No (Wayland only)
Hanging punctuation typesetting Yes (from 1.2.4-build1) Yes (from 1.2.5-build1)
Warichu (inline cutting notes) typesetting (one-line cases) Yes (from 1.2.4-build3) Yes (from 1.2.5-build1)
Japanese vertical text layout Experimental adjustment off by default Same (off by default)

The experimental vertical-text adjustment (it aligns vertical lines inside multi-column layouts to the column grid) is off by default on both Linux and Windows.
To turn it on, add --enable-blink-features=CJKVerticalColumnFragmentation to the executable's command line (passing arguments to blink_gtk_init() from your app does not reach it).
We have not compared the rendered output of the two operating systems side by side, so there is no guarantee that the layout matches.

The environment variable BLINKGTK_GPU_MODE does not change how rendering is handed over on Windows. Even with egl, the hand-over to GTK is the same as software (Chromium's internal rendering may differ; we have not measured the result). To try the GPU, use BLINKGTK_WIN_GPU_PATH below.
When you set an environment variable in cmd, put it in quotes like set "NAME=value" (with set NAME=value && … a trailing space becomes part of the value).

The experimental GPU path

Only when you set the environment variable BLINKGTK_WIN_GPU_PATH=vulkan, the result of Chromium's GPU compositing is handed to GTK's Vulkan renderer without being copied back into CPU memory (the usual path first copies the screen drawn by the GPU into CPU memory). A Vulkan-capable GPU and driver are required.

set "BLINKGTK_WIN_GPU_PATH=vulkan" && blinkgtk_browser.exe
  • It is experimental and confirmed on one Intel Iris Xe machine only. Other GPUs and drivers are unconfirmed. It is off by default.
  • At the same frames per second, CPU use was 12–26% lower on a moving page and about 50% lower on a still page (relative to the usual path), and the GPU was used 5–14%. Each is a single 120-second measurement, taken when this path was introduced. We have not measured power (watts).
  • Not checked: changes of the screen scaling (DPI), and multiple windows. Even on a still page it copies about 60 times a second (the GPU is used about 14%).
  • When Vulkan is not available (with a standard GTK, and with a simulated condition that points the Vulkan driver to a file that does not exist), it did not crash and the display did not break. We have not checked a machine that really has no driver.
  • Usage, what we checked and the limits are in §1 of the bundled docs\gpu-modes-ja.md (Japanese only).

If something goes wrong

  • If the window stays white or it exits at once: (1) start blinkgtk_browser.exe --enable-logging and note the messages printed in the console; (2) check that the ZIP is not corrupted with SHA256SUMS; (3) check that you have not mixed in a GTK4 installed another way. If that does not fix it, report it (below) with the messages you noted.
  • Bundled documents: §1 to §3 of docs\troubleshooting-en.md (Japanese: docs\troubleshooting-ja.md) have things to try, a symptom index and how to report (§4 and later are for people who build Chromium itself). For symptoms that are not there, please report them.
  • Documentation entry point: docs\00-index-en.md (Japanese: docs\00-index-ja.md). Installation is docs\INSTALLATION-en.md, Windows-specific notes on the API are docs\api-windows-notes-en.md, and environment variables are in docs\environment-variables-ja.md (Japanese only).
  • Reports and questions: please use Issues of blinkgtk-dist. Include the version (the output of --version), the Windows build number and the steps to reproduce.
