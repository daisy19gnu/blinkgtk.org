BlinkGTK GPU モード解説

BlinkGTK は、ページの描画に GPU を使うかどうかを 3 つのモードから選べます。
このページでは、選び方、指定の仕方、実行中に切り替えられる範囲、困ったときの確かめ方を説明します。

1. まず何を選べばよいか

用途 モード 指定
迷ったら / GPU の無い機械 / CI software 何も指定しない (既定)
GPU のあるデスクトップで、描画を GPU に任せたい egl BLINKGTK_GPU_MODE=egl
GPU は無いが WebGL / WebGPU を使うページを表示したい swiftshader BLINKGTK_GPU_MODE=swiftshader
  • 何も指定しなければ software で動きます。GPU ドライバに依存しないので、どの環境でも同じように表示されます
  • どのモードでも、表示には Wayland のコンポジタが要ります。画面の無い CI でも、headless のコンポジタ (weston の headless など) を使います
  • egl を指定しても GPU が使えない機械では、自動で software に切り替わります。描画データが 5 秒間 1 枚も届かなければ software へ切り替えて表示を続け、理由を標準エラー出力に出します (1.2.1-build2 から)。GPU が使える機械では切り替わりません
  • WebGL / WebGPU は software では使えません。使うページを表示するなら egl か swiftshader を選んでください (下の表)

2. 3 つのモード

software swiftshader egl
ページの描画 CPU CPU (合成は software と同じ) GPU
WebGL / WebGL 2 使えない 使える (CPU で計算) 使える
WebGPU 使えない 使える (CPU で計算) 使える
GPU とドライバ 要らない 要らない 要る (Wayland EGL に対応したもの)
向いている場面 電子書籍・キオスク・CI GPU の無い環境で 3D のページ GPU のあるデスクトップ

WebGL / WebGPU の可否は、Chromium 155 の版で各モードを試して確かめています (2026-10-13)。試したのは getContext('webgl')、getContext('webgl2')、navigator.gpu.requestAdapter() です。

software

  • Blink が CPU でページを描き、その結果を BlinkGTK が GTK のウィンドウに表示します
  • 描画結果の受け取り方は、起動したときの画面の拡大率で決まります (1.2.4 から)
    • すべての画面の拡大率が 1 のとき: mojo の共有メモリで受け取ります。描画結果を撮影して読み出す処理が要らず、合成の描き直しも変わった範囲だけになるので、部分的に動くページでの CPU 使用量が減ります
    • それ以外のとき: 描画結果を毎回撮影して受け取ります
    • 起動した後に拡大率が 1 より大きい画面へ移ると、撮影して受け取る方法へ 1 回だけ戻します。戻したときは、アプリが求めていなくても render-path-changed シグナルが届きます
  • 受け取り方を以前の版と同じ (撮影して受け取る) にするには、BLINKGTK_T2_AUTO=0 か BLINKGTK_USE_MOJO_IPC=0 を指定します。BLINKGTK_USE_MOJO_IPC を指定した場合は、その指定に従います。--force-device-scale-factor を指定した場合は、その値で判定し、起動した後に画面を移っても戻しません

swiftshader

  • ページの合成は software と同じで、WebGL / WebGPU の計算だけを SwiftShader (CPU で GPU の働きをするライブラリ) が受け持ちます
  • SwiftShader とその読み込みに要るファイルは配布物に入っています
  • 1.2.3-build2 より前の版では、画面に何も表示されないことがありました。1.2.3-build2 から修正されています

egl

  • Wayland の EGL を通して GPU で描画し、その結果を GPU のメモリのまま (dmabuf) GTK のウィンドウへ渡します。表示のために描画結果を CPU へ読み戻すことはしません (起動直後の数枚、GPU の受け渡しへ切り替えた直後の 1 枚、撮影を求めたときは CPU で読みます)
  • 実際の GPU と、Wayland EGL に対応したドライバが要ります
  • BLINKGTK_GPU_MODE=egl を指定するだけで動きます (1.2.0-build3 から。それ以前の版では白い画面になります)
  • ウィンドウの大きさを変えている間、一瞬白くなることがあります

3. 指定の仕方

起動する前に決めます。 次のどちらでも同じです。

BLINKGTK_GPU_MODE=egl ./myapp
blink_gtk_set_gpu_mode(BLINK_GPU_MODE_EGL);   /* blink_gtk_init() より前に呼ぶ (1.2.2-build5 から) */
blink_gtk_init(&argc, &argv);
  • 環境変数と blink_gtk_set_gpu_mode() の両方を指定した場合は、blink_gtk_set_gpu_mode() が優先します
  • モードは blink_gtk_init() の中で決まります。後から blink_gtk_set_gpu_mode() を呼んでも変わらず、警告が出るだけです
  • blink_web_view_new_with_gpu_mode() では、blink_gtk_init() の後にモードを選べません。WebView を作る時点ではモードが決まっているためです。モードは上の 2 つの方法で指定してください
  • モードはプロセス全体で 1 つです。WebView ごとに変えることはできません
  • 起動時に決まったモードは blink_web_view_get_gpu_mode() で確かめられます。起動完了のログにも「描画経路=<モード>」が出ます。egl から software へ自動で切り替わった後もこの値は egl のままです (5 章)

4. 実行中の切替 (BlinkShift)

BlinkShift は、アプリを再起動せずに、描画結果を画面へ受け渡す方法を切り替える機能です (1.2.0-build9 から)。
blink_web_view_switch_render_path() で切替を求め、結果は render-path-changed シグナルで届きます。
今の受け渡しの方法は blink_web_view_get_render_path() で分かります。

int seq = blink_web_view_switch_render_path(view, "P1");
/* 受け付けられれば 1 以上、受け付けられなければ 0 が返る。
 * 結果は render-path-changed (path_id, result, gate_ms, seq) で届く。 */

切替先に渡す値:

値 受け渡しの方法
"P1" software の描画結果を毎回撮影して受け取る
"P2" software の描画結果を mojo の共有メモリで受け取る
"P3" GPU (egl) の描画結果を GPU のメモリのまま受け取る

結果 (result) は次の 3 つです。

result 意味
"ok" 新しい方法で描画できた
"rollback" 新しい方法で描画を確かめられず、元の方法へ戻した。画面はそのまま
"fail" 元の方法へ戻せなかったか、切替を始められなかった。エラーとして扱ってください

どこからどこへ移れるか (Chromium 155、GPU のある機械、拡大率 1。headless のコンポジタで各 1 回試した結果。2026-10-13):

起動したモード 移れる 移れない
software "P1" ↔︎ "P2" (数十〜数百ミリ秒) "P3" (egl) — 受け付けられないか、rollback で元に戻る
egl "P1" (約 250 ミリ秒) "P2"

頁の背景の色による違い (1.2.4-build3 から):

  • 切替の後は、新しい方法で届いた画面を、切替の前に表示していた画面と比べて描画を確かめます。白い背景の頁でも、上の表のとおり移れます。1.2.4-build2 までは、白い背景の頁では描画できていても "rollback" になっていました
  • 黒い背景の頁で egl から "P1" へ移るときは、描画を確かめられないため "rollback" になります (表示は元のまま)。GPU のメモリの画面を CPU から読むと、環境によっては黒と区別がつかないためです

0 が返る (受け付けられない) のは、たとえば次の場合です。

  • 描画の最初のフレームがまだ届いていない
  • mojo の共有メモリ ("P2") か GPU のメモリ ("P3") で受け取っている間に、撮影して受け取る方法 ("P1") 以外を指定した
  • 知らない値、NULL、空の文字列を指定した
  • 診断用の環境変数 BLINKGTK_BLINKSHIFT_AUTOSWAP で自動の切替を動かしている

注意:

  • software で起動したプロセスは、実行中に egl へ移れません。 egl で描画するには、アプリを BLINKGTK_GPU_MODE=egl で起動し直してください
  • 起動し直すときの引き継ぎには、blink_web_view_export_handoff_meta() / blink_web_view_import_handoff_meta() を使えます
    • export したメタには、URL、表示領域の大きさ (論理ピクセル)、拡大率 (整数)、モード名 (環境変数 BLINKGTK_GPU_MODE の値) が入ります。スクロール位置の欄は 0 で書き出されるので、必要ならアプリが値を入れます
    • import が行うのは URL の読み込みだけです。大きさはアプリがウィンドウに設定し、スクロール位置は読み込みの後に JavaScript で戻します
    • 別のプロセスへ渡すには blink_handoff_meta_serialize() / blink_handoff_meta_deserialize() で文字列にします
  • 切替が掛かるのは、プロセスの中で最初に描画結果が届いた WebView の表示です。WebView が複数ある場合、引数の view は結果の通知の宛先を決めるだけです
  • seq の使い方は、シグナル API リファレンス の render-path-changed の節にあります。メタの詳細は 描画経路の切替と引き継ぎ を参照してください

画面への受け渡しを止めたい場合 (提示ポリシー)

「方法を変える」のではなく「今は画面に出す必要がない」場合 (音声だけを聞いている間など) は、
blink_web_view_set_presentation_policy() を使います。画面へ受け渡す費用だけを省き、
ページの組版と描画 (先読み) は止めません。止めている間でも、撮影
(blink_web_view_capture_screenshot_async() など) は成功し、その後も止めたままです (1.2.3-build2 から)。
1.2.4-build3 からは、software の撮影はほとんどの場合、要求した時点の画面を返し、画面へは出さずに終わることがあります。
提示ポリシーは、egl では今のところ効果がありません。

5. 困ったとき

egl を指定したのに software で動いているように見える

  • GPU が使えない機械では、5 秒後に software へ自動で切り替わり、理由が標準エラー出力に出ます。切り替わったかどうかは、この標準エラー出力の警告で確かめてください。 blink_web_view_get_gpu_mode()、起動完了のログの「描画経路=」、blink_web_view_get_render_path()、export した handoff meta のモード名は、切り替わった後も egl のまま (受け渡しの方法は GPU のメモリ = "P3") です
  • 自動の切替を止めるには BLINKGTK_EGL_AUTO_FALLBACK=0 を指定します (その場合、GPU が使えないと画面は白いままになります)。待ち時間は BLINKGTK_EGL_AUTO_FALLBACK_MS で変えられます
  • blink_gtk_init() の後でモードを指定していないか確かめてください (3 章)

画面が白いまま

  1. 読み込みが終わっているか (load-changed シグナルで BLINK_LOAD_FINISHED が届くか)
  2. 色だけの簡単なページで表示されるか (data:text/html,<body style='background:red'>TEST</body>。data: の URL では色を # で書かないでください。# 以降が切り捨てられます)
  3. egl なら、GPU とドライバが Wayland EGL に対応しているか。対応していなければ自動で software に切り替わるはずです (上)

それでも白い場合は、使っている版 (blink_gtk_get_version_full() の値)、モード、ウィンドウの大きさと拡大率を添えてご報告ください。

egl で表示が左上に小さく出る

1.2.0-build3 より前の版で、画面の拡大率が 1 以外のときに起きていた症状です。1.2.0-build3 から修正されています。egl の拡大率は、起動した時点の最初の画面から取ります。複数の画面で拡大率が違う場合や、起動した後に拡大率の違う画面へ移った場合は確かめていません。起きた場合は、ウィンドウの大きさと各画面の拡大率を添えてご報告ください。

6. 履歴

版 変わったこと
1.2.0-build3 egl が BLINKGTK_GPU_MODE=egl の指定だけで動くようになった
1.2.0-build9 BlinkShift (実行中の受け渡しの方法の切替)
1.2.1-build2 GPU が使えない機械で egl から software へ自動で切り替わるようになった
1.2.1-build3 egl で起動した場合に、BlinkShift で GPU の受け渡しの方法を扱えるようになった
1.2.2-build5 blink_gtk_set_gpu_mode() でコードからモードを指定できるようになった
1.2.3-build2 swiftshader で画面に表示されないことがあったのを修正した
1.2.4 すべての画面の拡大率が 1 のとき、software の描画結果を mojo の共有メモリで受け取るのが既定になった
1.2.4-build3 白い背景の頁でも、BlinkShift の切替が元に戻らなくなった
