BlinkGTK 1.2.7-build3 リリースノート

リリース日: 2026-11-23 / Chromium: 158.0.8127.36 / 言語: 日本語 | English

build3: 一部の Web API でページが止まる問題の修正と、離脱の確認・言語・クライアント証明書・ドラッグの修正

build2 までをお使いの方は、build3 へ更新してください。公開 API に変更はない (公開ヘッダは説明の文だけが変わった) ので、アプリを作り直す必要はありません。

ただし、blink_web_view_set_javascript_dialog_handler() でハンドラを設定しているアプリは、下の「ページを離れる前の確認がハンドラに届く」を読んでください。ハンドラが種類を見ずに TRUE を返している場合は、対応が必要です。

ページが異常終了・停止しなくなった Web API — 次の API を呼ぶページは、build2 までは表示が止まっていました。build3 では、それぞれ「使えない」という結果を返し、ページはそのまま動きます。どのサイトでも起こりうるので、一般の Web ページを表示するアプリに関係します。

  • バッジ (navigator.setAppBadge() / navigator.clearAppBadge()): HTTPS などの安全なページから呼ぶと、ページが異常終了していました。build3 では何もせずに終わります (アプリにバッジは表示されません)。Service Worker から呼ぶ場合は試していません。
  • 端末内の音声認識の問い合わせ (SpeechRecognition.available() に processLocally: true を付けたもの、SpeechRecognition.install()): ページが異常終了していました。build3 では available() は "unavailable"、install() は false を返します。BlinkGTK は端末内の音声認識を持っていません。
  • Web アプリのインストール (navigator.install()): 結果が返らないまま止まっていました。build3 ではすぐに AbortError で失敗します。<install> 要素は試していません。

ページを離れる前の確認がハンドラに届く — ページが beforeunload で「変更が保存されていません」といった確認を求めたとき、build2 までは JavaScript ダイアログのハンドラは呼ばれず、常にそのままページを離れていました。build3 では、ハンドラに dialog_type = BLINK_JS_DIALOG_BEFORE_UNLOAD で届きます。応答の success は TRUE でページを離れ、FALSE でページにとどまります。message は決まった英語の文で、ページは文言を変えられません。ページがこの確認を求めるのは、利用者がそのページを操作した後だけです。

  • ハンドラを設定していない場合と、ハンドラがこの種類に FALSE を返した場合は、今までと同じくすぐにページを離れます (ハンドラを設定していない場合は試していません。コード上は今までと同じ動きです)。
  • ハンドラが TRUE を返したのに応答を返さないと、ページの移動は進みません。種類を見ずに TRUE を返しているハンドラは、BLINK_JS_DIALOG_BEFORE_UNLOAD を扱うか、この種類には FALSE を返すように直してください。

サーバーへ伝える言語が環境に合う — build2 までは、どの言語の環境でも、サーバーに送る言語 (HTTP の Accept-Language) は en-us,en、navigator.languages は en-US でした。そのため、言語で表示を変えるサイトは、日本語の環境でも英語の版を返していました。build3 では、起動時に --lang を渡した場合はその言語、渡していない場合は環境変数 LC_ALL・LC_MESSAGES・LANG の順に最初に値のあるものから決めます。

  • 例: LANG=ja_JP.UTF-8 では、Accept-Language は ja-JP,ja;q=0.9,en-US;q=0.8,en;q=0.7、navigator.languages は ja-JP,ja,en-US,en になります。
  • LANG=C では、Accept-Language は今までと同じ en-us,en です。navigator.languages は en-US から en-US,en に変わります。
  • 英語のページを受け取る前提のアプリは、言語の環境によってサイトの返す内容が変わることがあります。英語のままにしたい場合は、LANG=C で起動してください。

クライアント証明書を任意で求めるサイトが開ける — TLS の接続でクライアント証明書を「任意で」求めるサイトは、build2 までは読み込みに失敗していました。build3 では、証明書を送らずに接続を続け、ページが表示されます。証明書を選ぶ画面や API はなく、証明書は送りません。証明書を必須とするサイトは試していません。

ページの中のドラッグの後にクリックが届く — ページの中で文字・画像・リンクをドラッグすると、build2 まではページがドラッグの途中のまま残り、その後のクリックがページに届きませんでした。build3 では、ドラッグはすぐに取り消しとして終わり (ページには何もドロップされなかったと伝わります)、その後のクリックは今までどおり届きます。ドラッグ・アンド・ドロップそのものには対応していません。ページの中でドロップすることはできず、ファイルマネージャーからファイルをドロップしても受け付けません。この確認は、試験用に送ったマウスの操作で行いました。

build2: 古い画面を出さないための修正と、X11 向けコードの除去

build1 をお使いの方は、build2 へ更新してください。公開 API に変更はないので、アプリを作り直す必要はありません。

古い画面を出さない — 拡大率 1 の画面でソフトウェア描画を使うときの既定の経路で、いま表示しているページの描画を含まないフレームは、画面へ出さずに捨てるようにしました。また、画面へ出すのを止めている間 (blink_web_view_set_presentation_policy() で BLINK_PRESENT_WARM を指定したとき、または BLINKGTK_PRESENT_POLICY=warm で窓が隠れている間) に取っておいた画面は、その後にページが描き直されていれば、表示を再開したときに出さずに捨てます。前の画面や、ページがまだ入っていない画面が表示されないようにするための修正です。拡大率が 1 以外の画面と、GPU を使う描画には関係しません。

X11 向けのコードを外しました — BlinkGTK の Linux 版は Wayland だけで動きます。使っていなかった X11 向けのコードをライブラリから外しました。使い方と見た目は変わりません。

build1: Chromium 158 へ更新

BlinkGTK のレンダリングエンジンを Chromium 158.0.8127.36 に更新しました。

セキュリティ (Chromium 158)

Chromium 158 のデスクトップ安定版には、上流のセキュリティ修正 204 件が含まれています。修正の詳細はChromium の公式発表をご覧ください。

このリリースは Linux 向けです。以前の版をお使いの場合は、セキュリティ修正を含む本版へ更新してください。

描画と console 出力

software の既定経路では、ページの変わった範囲を GTK と Wayland に更新範囲として渡します。BLINKGTK_T2_DAMAGE=0 で従来の全体更新に戻せます。小さな範囲が変わるページでは合成器へ渡す面積が減りますが、アプリの CPU 時間が下がるとは確認されていません。

BLINKGTK_CONSOLE_STDOUT=0 を指定すると、ページの console メッセージを標準出力へ出さないようにできます。既定では出力します。BlinkGTK のメッセージブリッジには影響しません。

通常の Linux 起動は Wayland 専用です。公開 API に変更はありません。
