WebKitGTK (C、約20-30行):

#include <gtk/gtk.h>
#include <webkit/webkit.h>

static void activate(GtkApplication *app, gpointer data) {
  GtkWidget *window = gtk_application_window_new(app);
  GtkWidget *webview = webkit_web_view_new();
  gtk_window_set_child(GTK_WINDOW(window), webview);
  webkit_web_view_load_uri(WEBKIT_WEB_VIEW(webview), "https://example.com");
  gtk_window_present(GTK_WINDOW(window));
}

int main(int argc, char *argv[]) {
  GtkApplication *app = gtk_application_new("org.example.browser", 0);
  g_signal_connect(app, "activate", G_CALLBACK(activate), NULL);
  return g_application_run(G_APPLICATION(app), argc, argv);
}

BlinkGTK (C、約25-35行):

#include <gtk/gtk.h>
#include <blink_gtk/blink_gtk.h>

static void activate(GtkApplication *app, gpointer data) {
  blink_gtk_init(NULL, NULL);
  GtkWidget *window = gtk_application_window_new(app);
  GtkWidget *webview = blink_web_view_new();
  gtk_window_set_child(GTK_WINDOW(window), webview);
  blink_web_view_load_uri(BLINK_WEB_VIEW(webview), "https://example.com");
  gtk_window_present(GTK_WINDOW(window));
}

int main(int argc, char *argv[]) {
  GtkApplication *app = gtk_application_new("org.example.browser", 0);
  g_signal_connect(app, "activate", G_CALLBACK(activate), NULL);
  return g_application_run(G_APPLICATION(app), argc, argv);
}

2. 技術要件

項目 CEF WebKitGTK BlinkGTK
Chromiumソース必要 不要（バイナリ配布あり） 不要 必要（ソースビルド必須）
ソースからのビルド時間 2-4時間（Chromiumフルビルド） 1-2時間 3-5時間（Chromiumフルビルド）
インクリメンタルビルド 分-時間 分 Tier 1: 30秒 / Tier 2: 8分 / Tier 3: 2-3時間
必要ディスク容量（ビルド） 80-120GB 15-25GB 80-120GB
必要RAM（ビルド） 16GB以上推奨 8GB以上 16GB以上推奨
ビルドシステム CMake / GN CMake GN (ninja)

項目 CEF WebKitGTK BlinkGTK

7. BlinkGTKの位置づけ

7.1 CEFとの差異

観点 CEF BlinkGTK
GTK統合 なし（独自ウィンドウ管理） GTK4ネイティブ（GtkGLArea / GtkDrawingArea）
GObject なし（C++ API） GObject型システム完全対応
言語バインディング C++ / Java / C# C / Python / Rust / Vala / GJS / Go（GIR経由）
パッケージ配布 アプリケーション同梱 RPM / DEB システムパッケージ
バイナリサイズ 150-200MB 65-80MB
設計思想 クロスプラットフォーム埋め込み GTK4 / Wayland専用統合

CEFはクロスプラットフォームの汎用埋め込みフレームワークとして設計されている。一方、BlinkGTKはGTK4エコシステムへのネイティブ統合を目的としており、WebKitGTKと同等のAPI体験を提供することを目指している。

7.2 WebKitGTKとの差異

観点 WebKitGTK BlinkGTK
エンジン WebKit (JavaScriptCore) Blink (V8)
Web標準対応率 95-98% 98-100%
Chrome互換性 低-中 Chromium同等（完全）
Safari互換性 完全 低-中
X11対応 あり なし（Wayland専用）
API成熟度 安定（10年以上の歴史） 開発版（v1.0.0-rc2）
コンテンツポリシー カスタム実装が必要 プリセット内蔵（電子書籍/キオスク）
ディストリビューション標準 はい（Fedora/Ubuntu等） いいえ（独自配布）

WebKitGTKはLinuxデスクトップのデファクトスタンダードであり、GNOME Web（Epiphany）をはじめ多くのアプリケーションで使用されている。BlinkGTKはChromiumベースのWeb標準対応とChrome DevTools互換性が必要な場面での選択肢となる。

7.3 想定ユースケース

BlinkGTKが適するケース:

ユースケース 理由
電子書籍リーダー コンテンツポリシープリセット内蔵、CSS Paged Media対応
キオスク端末 コンテンツ保護機能、フルスクリーンAPI
GTK4ネイティブブラウザ GObject統合、GIRバインディング
Chrome互換が必要なアプリ Blink エンジンによる高い Chrome 互換性
Waylandネイティブアプリ X11不使用、Waylandプロトコル直接使用
多言語バインディングが必要 Python / Rust / Vala / GJS / Go 対応

BlinkGTKが適さないケース:

ケース 理由 代替
X11環境 Wayland専用 CEF または WebKitGTK
Windows / macOS Linux専用 CEF
軽量アプリ Chromiumベースのためメモリ消費が大きい WebKitGTK
GTK3アプリ GTK4専用 WebKitGTK (GTK3版)
Safari互換が必要 WebKitではなくBlink WebKitGTK
安定版APIが必須 現在v1.0.0-rc2 WebKitGTK

7.4 既知の制限事項

  • Wayland専用: X11環境では動作しない
  • Component Build: 約30-40の共有ライブラリが必要（静的リンク版は未提供）
  • API安定性: v1.0正式リリース前のためAPIが変更される可能性がある
  • GtkGLAreaモードの上限: SwiftShader使用時の描画は62.4fps程度（ハードウェアGPU使用時は改善の余地あり）
  • プロセスモデル: シングルプロセスモードで動作（マルチプロセス分離は未対応）
