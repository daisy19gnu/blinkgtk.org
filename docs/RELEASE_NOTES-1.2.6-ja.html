BlinkGTK 1.2.6-build1 リリースノート

リリース日: 2026-11-04 / Chromium: 157.0.8103.38 / 言語: 日本語 | English

レンダリングエンジンを Chromium 157 に更新しました。日本語の縦書きを扱う方へのポイントは次の 4 点です。

  • ルビの付いた字に下線・傍線を引いても、線とルビが重ならなくなりました
  • 家族などのつないだ形の絵文字が、縦書きでも 1 つの絵文字として表示されます
  • 下線・傍線の両端を詰める text-decoration-inset が使えます (縦書きでも線が短くなります)
  • 横書きでは、要素の境目でも波線の模様が続くようになりました。縦書きは変わりません

起動も速くなりました (この版の測定で、頁の読み込みの完了が約 0.3 秒早い)。

  • 前の版から上げる方は、以前の版から上げる方へ の表で、使い方に当たる行を確かめてください
  • 初めて使う方は インストール から始めてください
  • WebKitGTK・CEF・Electron から乗り換える方は、WebKitGTK からの移行・CEF・Electron からの移行 を見てください

build1: Chromium 157 の最初の版

この build1 は Linux 向けパッケージです (例: blinkgtk-1.2.6-build1-linux-x86_64.tar.gz)。Chromium は 157.0.8103.38 です。この版で変わったことは、以下の各節に書きました。

縦書きでできるようになったこと (Chromium 157)

図 1: 同じ頁を 1.2.5 と 1.2.6 で開いたところ 左から、ルビだけの行、ルビの付いた字に傍線を引いた行、家族の絵文字を入れた行。

ルビの付いた字に傍線を引いても、線とルビが重ならない

日本語の縦書きでは、下線 (text-decoration: underline) は字の右側、つまりルビと同じ側に引かれます。1.2.5 までは線とルビが同じ位置に描かれ、ルビの上を線が通っていました (図 1 の左から 2 列目)。

1.2.6 では、線を引いた字のルビが線の外側へ移り、重なりません。ルビだけの行の配置は変わりません。

<p style="writing-mode: vertical-rl" lang="ja">
  <span style="text-decoration: underline"><ruby>漢字<rt>かんじ</rt></ruby></span>の読み
</p>
  • 確かめたこと: 上の形の頁で、ルビの位置を 1.2.5 と 1.2.6 で測りました。傍線を引いた行だけ、1.2.6 でルビが線の外側へ 3px 移ります (文字の大きさ 28px のとき)。傍線のない行は両方の版で同じ位置です。
  • ルビが線の分だけ外へ出るので、ルビの外側に余白の少ない組版では、隣の行との間が詰まって見えることがあります。

家族などの絵文字が、縦書きでも 1 つの絵文字として表示される

👨‍👩‍👧 のように、いくつかの絵文字を見えない結合の文字 (ZWJ) でつないだものは、1 つの絵文字として表示されます。1.2.5 までは縦書きにすると部品ごとに分かれ、3 人が縦に並んでいました (図 1 の左から 3 列目)。1.2.6 では横書きと同じく 1 つの絵文字になります。

  • 確かめたこと: 縦書きの行で、この絵文字の範囲の高さを測りました。1.2.5 では 102.6px (3 字分)、1.2.6 では 34.2px (1 字分) です。
  • 書体に、つないだ形の絵文字が入っている必要があります (この確認では Noto Color Emoji を使いました)。

下線・傍線の両端を詰められる (text-decoration-inset)

下線や傍線の始まりと終わりを、字の端から内側へ詰める指定です。1.2.3〜1.2.5 では使えず、指定しても無視されていました。1.2.6 から使えます。縦書きでは、線の上端と下端が詰まります。

/* 線の両端を 2px ずつ内側へ */
.underlined { text-decoration: underline; text-decoration-inset: 2px; }
  • 確かめたこと: 文字の大きさ 40px の 5 字に縦書きで下線を引き、text-decoration-inset: 10px を指定して線の長さを画素で測りました。1.2.6 では 200px が 180px になり、上下 10px ずつ詰まります。1.2.5 では指定が無視され 200px のままです。

縦書きでは変わらないこと: 波線の途切れ

Chromium 157 では、波線の下線 (text-decoration: underline wavy) が、途中の <em> などの要素の境目で模様をやり直さず、続けて描かれるようになりました。これは横書きの場合だけです。

縦書きでは、1.2.6 でも要素の境目で波の模様がやり直されます (1.2.5 と同じ)。縦書きの波線の途中に強調などを入れると、境目で波がずれて見えます。

  • 確かめたこと: 同じ文を、途中を <em> で囲んだものと囲まないもので並べ、波線の画素の位置を比べました。横書きでは 1.2.6 で差がなくなり、縦書きでは 1.2.5 と 1.2.6 で同じだけ差が残ります。

縦書きの行を最後まで埋める (Chromium 157 で起きる問題を防ぐ)

Chromium 157 では、縦組みの行末に閉じ括弧などがあるとき、行の長さを使い切る前に改行してしまうことがあります。行が途中までしか埋まらず、半分ほどの長さで折り返します。Chromium 157 で、この問題を防いでいた処理が既定で止められたためです (別の頁で異常終了が見つかったための措置)。

1.2.6 では、異常終了を直したうえでこの処理を元に戻す上流の修正を取り込みました。上流では Chromium 158 から入る見込みの修正です。

  • 確かめたこと: 縦書きの 1 行目に 35 字すべてが入り、字が欠けないこと。行の長さを 544〜564px の間で 1px ずつ変えたときと、句読点・ルビ・書体などを変えた 13 の条件で、1 行の字数が 1.2.5 と同じになること。上流で異常終了が見つかった頁を開いても、頁の表示が止まらないこと。

起動が速くなりました

ファイルを選ぶ API を使えるまま、起動を速くしました。1.2.5-build5 で外した起動の短縮 (共有ライブラリを読み込むときのシンボルの検索を減らす指定) を、build2〜build4 でアプリが異常終了する原因になった部分を除いて入れ直したものです。1.2.6 で、ページからファイルを選ぶ API を呼んでもアプリが異常終了しないことを確かめています。

起動の時間 (Intel Core i5-10310U・Fedora 45 の機械 1 台、試験用の頁、描画の経路ごとに 5 回ずつの中央値、2026-11-04 測定):

区切り 描画の経路 1.2.5-build5 1.2.6 差
初期化 (blink_gtk_init()) が終わるまで software 493 ms 334 ms −159 ms
最初の描画が届くまで software 1,259 ms 917 ms −342 ms
頁の読み込みの完了 software 1,237 ms 895 ms −342 ms
頁の読み込みの完了 EGL 1,387 ms 1,054 ms −333 ms

Chromium の版も変わっているので、速くなった分のうち、どれだけが起動の短縮によるものかは分けて測っていません。測ったのは 1 台・1 つの頁です。

部分的な描き直しの既定を変えました

頁の一部だけが変わる場面 (動く頁など) で、内容が切り替わるたびに画面全体を描き直していた処理を、既定で止めました。白いページが出るのを防ぐために入れていたものですが、今の版の確認では、止めても白いページは出ませんでした。別の仕組み (描き直しの指示が抜けたときに全面を描き直す処理) は残しています。

  • 1.2.5 でこの処理を止めて測ると、部分的に変わる頁を 16 秒表示する間に、画面を合成するスレッドの CPU 時間が約 2 秒減りました (2 台の機械で同じ大きさ)。1.2.6 では測っていません。
  • 1.2.6 では、この変更の後に、白いページ・描画・アニメーションなど描画に関わる確認を行い、問題が無いことを確かめました。
  • 前と同じ動きに戻すには、環境変数 BLINKGTK_120_ACT_REDRAW=1 を設定してアプリを起動します。1.2.6 で白いページを見たときは、この設定で消えるかを確かめて知らせてください。

Chromium 157 で使えるようになったもの (主なもの)

  • text-overflow に文字列を指定できます。はみ出した部分を「…」の代わりに指定した文字列で示します (例: text-overflow: "…続く")。1.2.5 では指定が無視されていました
  • 可変フォントで font-style: italic や oblique を指定すると、書体の斜体の軸が使われます
  • Canvas に頁の要素 (HTML) を描けます (drawElement)
  • Canvas の色空間に、線形の色空間 (srgb-linear・display-p3-linear) を指定できます
  • WebTransport で、接続のときに送るヘッダを指定し、サーバーが返したヘッダを読めます

Chromium 157 では、設定の項目 (機能を切り替えるフラグ) が 27 個無くなりました。そのうち 1.2.5 で既定で有効だったものは、機能が常に有効になってフラグが片付けられたものです。たとえば calc() で単位どうしを割る計算と overscroll-behavior: chain は、1.2.5 と 1.2.6 の両方で使えることを確かめました。
